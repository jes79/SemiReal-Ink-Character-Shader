# 4차시. 먹 아웃라인과 스타일 프리셋

| 항목 | 내용 |
|---|---|
| 수업 시간 | 180분 (도입 10 · 시연 25 · 개념 45 · 쉬는 시간 10 · 실습 70 · 정리·과제 20) |

## 학습 목표

1. 먹 아웃라인이 "뒷면을 부풀려 한 번 더 그리는 패스"이고, 굵기를 화면 픽셀 단위로 맞춘다는 것을 코드에서 찾아 설명할 수 있다.
2. `[ToggleUI]` 값 스위치와 키워드(`[Toggle(…)]`·`[KeywordEnum(…)]`)의 차이를 말하고, 언제 무엇을 쓸지 고를 수 있다.
3. `StylePreset` 에셋을 새로 만들어 `Styles` 목록에 넣고, 쉐이더부터 패널까지 기능 스위치 하나를 빠짐없이 더할 수 있다.

## 시연 순서

### A. 먹 선 들여다보기 (10분)

1. ▶ 플레이. **비교** 탭 → **A (왼쪽)** = `세미리얼`, **B (오른쪽)** = `스타일라이즈드`. 비교 방식은 **와이프 (1)**.
2. 휠로 얼굴까지 확대했다가 전신까지 축소한다. "선 굵기가 화면에서 거의 그대로"를 보여 준다.
   - 세미리얼은 가늘고 옅은 선, 스타일라이즈드는 굵고 진한 선.
3. `O` 키를 몇 번 누른다. A·B **양쪽 선이 같이** 사라졌다 생긴다 (기능 스위치는 두 쪽에 똑같이 걸림).
4. **맵·보기** 탭 → 디버그 보기 **노멀 (방향 색)** → 선이 사라진다. **빛만 (회색 점토)** → 선이 다시 보인다. **보통 화면**으로 돌린다.
   - "아웃라인은 보통 화면과 빛만 보기에서만 그린다"를 말해 둔다 (개념 1에서 코드로 확인).

### B. 스위치 규칙: "끄기만 한다" (8분)

5. **쉐이더** 탭 → "스타일 프리셋 (B 쪽)"에서 **리얼** 카드를 누른다.
6. "기능 켜고 끄기"에서 **먹 아웃라인**을 껐다 켠다. B(리얼)에는 **켜도 선이 생기지 않는다**.
   - 리얼 프리셋이 아웃라인을 `Off`로 덮어쓰기 때문. 스위치는 그 위에서 "끄기"만 할 수 있다.
7. **스타일라이즈드** 카드 → **역광 (림 라이트)** 를 끈다. A(세미리얼)의 테두리 빛도 함께 사라진다.
8. 끈 스위치를 모두 다시 켠다.

### C. 프리셋 에셋 열어 보기 (7분)

9. 플레이를 **멈춘다**.
10. Project 창 `Assets/CharacterShaderTest/Settings/Styles/` → `3_Stylized` 선택. 인스펙터를 보여 준다.
    - 머리글: **명암 · 반사 · 보조광·역광 · 먹 아웃라인 · 기능 (Keep = 머티리얼 값 그대로)**
    - 숫자 칸(예: **Outline Width**)을 펼치면 **Enabled** 체크 + **Value**
    - 기능 칸(예: **Outline**)은 **Keep / On / Off** 드롭다운
11. `1_Real`, `2_SemiReal`도 열어 비교한다. `2_SemiReal`은 **Enabled가 하나도 없고 기능이 모두 Keep** = "아무것도 덮어쓰지 않는 프리셋".
12. Hierarchy `Shader Lab` → `Shader Lab Controller` → "프리셋" 머리글 아래 **Styles** 목록(3개)을 보여 준다. "오늘 여기에 4번째를 넣는다."

## 개념 설명

### 1. 용어

| 용어 | 한 줄 풀이 |
|---|---|
| 앞면 / 뒷면 (Front / Back Face) | 삼각형이 카메라를 보고 있으면 앞면, 등지고 있으면 뒷면 |
| 컬링 (Cull) | 앞면이나 뒷면을 아예 안 그리고 버리는 설정. `Cull Back`(뒷면 버림)이 보통 |
| 정점 (Vertex) | 메쉬의 꼭짓점. 버텍스 쉐이더가 꼭짓점 위치를 옮길 수 있다 |
| 클립 공간 (Clip Space) | 화면에 찍기 직전의 좌표. `xy`를 `w`로 나누면 화면 위치(-1~1)가 된다 |
| 키워드 (Keyword) | 쉐이더 코드의 `#if`를 켜고 끄는 이름표. 켜짐/꺼짐마다 쉐이더가 따로 만들어진다 |
| 배리언트 (Variant) | 키워드 조합마다 따로 컴파일된 쉐이더 한 벌 |
| SRP Batcher | 같은 쉐이더 머티리얼을 빨리 그리는 URP 기능. 머티리얼 값이 `UnityPerMaterial` 버퍼에 모여 있어야 동작 |
| ScriptableObject | 값만 담아 두는 에셋(`.asset`)을 만드는 C# 클래스. `StylePreset`이 이것 |

### 2. 먹 아웃라인 = 뒷면을 부풀려 한 번 더 그리기

[그림: ① 원래 캐릭터 ② 같은 메쉬를 노멀 방향으로 조금 부풀린 것(뒷면만 남김, 검은색) ③ ①을 ② 위에 겹치면 바깥으로 삐져나온 띠만 보임 = 외곽선]

순서는 이렇습니다.

1. 본체 패스(`ForwardLit`)가 캐릭터를 그린다.
2. 같은 메쉬를 **아웃라인 패스**(`InkOutline`)가 한 번 더 그린다. 이때
   - 꼭짓점을 바깥쪽(노멀 방향)으로 조금 민다 → 캐릭터보다 살짝 뚱뚱한 껍데기
   - **앞면은 버리고 뒷면만** 그린다 (`Cull Front`)
3. 껍데기의 뒷면은 몸 뒤쪽에 있으므로 대부분 본체에 가려진다. **윤곽 바깥으로 삐져나온 띠만** 보인다 → 외곽선.

> **노멀(Normal)**: 표면이 바라보는 방향 화살표 (2차시).

**패스 머리** (`SemiRealInk.shader` 616–627행, 찾을 글자: `Name "InkOutline"`)

```hlsl
// 2. 먹 아웃라인 (뒷면을 부풀려 그리기)
Pass
{
    Name "InkOutline"
    Tags { "LightMode" = "SRPDefaultUnlit" }

    Cull Front
    ZWrite On
    // 본체보다 아주 살짝 뒤로 밀어, 양면 옷의 안쪽 면 위에 먹이 덮이지 않게 한다
    Offset 1, 1
    Blend SrcAlpha OneMinusSrcAlpha
```

| 줄 | 설정 | 뜻 |
|---|---|---|
| 621 | `"LightMode" = "SRPDefaultUnlit"` | URP가 본체와 함께 그려 주는 "추가 패스" 표시 |
| 623 | `Cull Front` | 앞면 버림 → 뒷면만 그림. 본체(`Cull [_Cull]`, 268행)와 반대 |
| 624 | `ZWrite On` | 깊이를 기록 |
| 626 | `Offset 1, 1` | 깊이를 아주 조금 뒤로 → 양면 옷 안감 위에 먹이 덮이지 않음 |
| 627 | `Blend SrcAlpha OneMinusSrcAlpha` | 반투명 섞기 → 먹이 옅게 번진 느낌 (`Ink Opacity`) |

### 3. 픽셀 굵기: 멀어도 가까워도 같은 두께

정점을 밀 때 **미터가 아니라 화면 픽셀**로 밉니다 (690–701행, 찾을 글자: `float4 tipCS`).

```hlsl
float3 objectOriginWS = TransformObjectToWorld(float3(0, 0, 0));
float brush = ValueNoise3D((positionWS - objectOriginWS) * _OutlineNoiseScale);
float widthScale = lerp(1.0, brush * 1.6, _OutlineNoiseAmount);

// 노멀 방향 한 점을 함께 투영해 화면에서의 실제 방향을 구한 뒤, 픽셀 단위로 일정한 굵기만큼 밀어낸다
float4 tipCS = TransformWorldToHClip(positionWS + normalWS * 0.01);
float2 ndcDelta = tipCS.xy / tipCS.w - positionCS.xy / positionCS.w;
float2 dirPixels = SafeNormalize(float3(ndcDelta * _ScreenParams.xy, 0)).xy;
float2 pixelToNdc = float2(2.0 / _ScreenParams.x, 2.0 / _ScreenParams.y);
positionCS.xy += dirPixels * pixelToNdc * (_OutlineWidth * widthScale) * positionCS.w;
```

| 줄 | 하는 일 (쉬운 말) |
|---|---|
| 697 | 꼭짓점에서 노멀 쪽으로 1cm 떨어진 점도 화면에 찍어 본다 |
| 698–699 | 두 점의 화면 위치 차이 = "화면에서 바깥쪽" 방향. 길이 1로 맞춘다 |
| 700 | 1픽셀이 화면 좌표(-1~1)로 얼마인지. 화면 폭이 2칸이므로 `2 / 화면 픽셀 수` |
| 701 | 그 방향으로 `_OutlineWidth`(픽셀) 만큼 민다. 끝의 `* positionCS.w`는 GPU가 나중에 `w`로 나누는 것을 미리 상쇄 → **거리와 상관없이 같은 픽셀** |

| 방식 | 미는 단위 | 카메라가 멀어지면 | 이 쉐이더 |
|---|---|---|---|
| 월드(미터) 굵기 | 0.01m 등 | 선이 가늘어지다 사라짐 | 아님 |
| 화면 픽셀 굵기 | `Width (Pixels)` | 선 굵기가 그대로 | **이것** (`_OutlineWidth`, 128행 `Range(0, 8)`) |

**붓 느낌** (692–694행): `ValueNoise3D`는 위치마다 0~1 사이로 천천히 변하는 값(노이즈)을 줍니다. 이 값으로 굵기를 들쭉날쭉하게 합니다.

| 프로퍼티 (인스펙터 이름) | 줄 | 하는 일 |
|---|---|---|
| `_OutlineColor` (Ink Color) | 127 | 먹 색 |
| `_OutlineWidth` (Width (Pixels)) | 128 | 굵기, 픽셀 |
| `_OutlineOpacity` (Ink Opacity) | 129 | 진하기 (반투명) |
| `_OutlineBaseBlend` (Blend With Base Color) | 130 | 먹에 바탕색을 섞는 양 |
| `_OutlineNoiseScale` (Brush Noise Scale) | 131 | 붓 자국 크기 (클수록 잘게 변함) |
| `_OutlineNoiseAmount` (Brush Variation) | 132 | 굵기·농도가 들쭉날쭉한 정도. 0 = 일정 |

**픽셀 버리기** (714–723행, 찾을 글자: `clip(_EnableOutline`)

```hlsl
int debugView = (int)(_ShaderLabDebugView + 0.5h);
clip(_EnableOutline - 0.5h);
clip((debugView == 0 || debugView == 7) ? 1.0h : -1.0h);
```

> **clip(x)**: x가 0보다 작으면 그 픽셀을 버린다 (색도 깊이도 안 남음).

- 717행: `Ink Outline` 체크(`_EnableOutline`)가 0이면 전부 버림 → 선이 사라짐.
- 718행: 디버그 보기가 0(보통 화면)이나 7(빛만)이 아니면 버림 → 시연 4번에서 본 것.
- 주의: 끈 상태에서도 아웃라인 패스는 **그리러 들어간 뒤 픽셀만 버립니다**. 키워드처럼 패스 자체를 없애는 것은 아닙니다 (아래 4절).

### 4. `[ToggleUI]` 값 스위치 vs 키워드

이 쉐이더에는 "켜고 끄는 칸"이 두 종류 있습니다.

**값 스위치** (47–54행, `[Header(Features)]` 아래)

```hlsl
[ToggleUI] _EnableSpecular ("Specular Highlight", Float) = 1
...
[ToggleUI] _EnableOutline ("Ink Outline", Float) = 1
```

코드에서는 **곱하기**로 씁니다 (찾을 글자: `* _EnableSpecular`, 520행).

```hlsl
half specScale = _SpecularStrength * surfaceSpec * metalBoost * _EnableSpecular;
```

**키워드 스위치** (57·98행, 그리고 276–277행)

```hlsl
[KeywordEnum(Standard, Skin, Cloth)] _MaterialType ("Material Type", Float) = 0
[Toggle(_MASKMAP)] _UseMaskMap ("Use Mask Map (R Metal, G Gem, B Silver)", Float) = 0

#pragma shader_feature_local _MATERIALTYPE_STANDARD _MATERIALTYPE_SKIN _MATERIALTYPE_CLOTH
#pragma shader_feature_local_fragment _MASKMAP
```

코드에서는 **`#if`** 로 씁니다 (찾을 글자: `#if defined(_MASKMAP)`, 352행).

| | `[ToggleUI]` 값 스위치 | 키워드 (`[Toggle(…)]`, `[KeywordEnum(…)]`) |
|---|---|---|
| 정체 | 숫자 0/1 | `#if`를 켜고 끄는 이름표 |
| 쉐이더 안에서 | `* _EnableX` 곱하기, `clip` | `#if defined(…)` 로 코드 덩어리를 넣고 뺌 |
| 배리언트 | **늘지 않음** | 켜짐/꺼짐마다 한 벌씩 → 개수가 곱으로 늘어남 |
| 꺼졌을 때 GPU 일 | 계산은 하고 0을 곱함 (조금 낭비) | 그 코드가 아예 없음 (가장 빠름) |
| C#에서 바꾸기 | `SetFloat` 한 줄 | `SetFloat` + `EnableKeyword`/`DisableKeyword` 둘 다 |
| 이 쉐이더에서 | 기능 스위치 8개, 맵 사용 6개 | 재질 타입(피부·천), 마스크 맵 |
| 어울리는 곳 | 실행 중에 자주 껐다 켜는 것 (랩의 스위치) | 머티리얼마다 정해지고 잘 안 바뀌는 큰 갈래 |

**배리언트 계산**: 기능 스위치 8개를 키워드로 만들면 2×2×…×2 = 2⁸ = **256배**. 여기에 재질 타입 3 × 마스크 2 = 6이 다시 곱해집니다. 그래서 README도 "키워드가 아니라 값으로 처리해서 체크를 바꿔도 쉐이더 종류(배리언트)가 늘지 않습니다"라고 적어 두었습니다.

**키워드는 C#에서 손이 더 간다** — 장면 메뉴 코드(`Editor/SemiRealInkTestSetup.cs`)를 보면 값과 키워드를 **둘 다** 바꿉니다.

```csharp
// SetSurfaceType (283–290행, 찾을 글자: "static void SetSurfaceType")
m.SetFloat("_MaterialType", (float)type);
m.DisableKeyword("_MATERIALTYPE_STANDARD");
m.DisableKeyword("_MATERIALTYPE_SKIN");
m.DisableKeyword("_MATERIALTYPE_CLOTH");
m.EnableKeyword("_MATERIALTYPE_" + type.ToString().ToUpperInvariant());

// AssignMaskMap (183–185행)
m.SetFloat("_UseMaskMap", mask != null ? 1f : 0f);
if (mask != null) m.EnableKeyword("_MASKMAP");
else m.DisableKeyword("_MASKMAP");
```

반면 랩의 기능 스위치는 `SetFloat` 한 줄이면 끝납니다 (`LabCharacter.cs` 117행).

> `shader_feature`(키워드)는 빌드할 때 **어떤 머티리얼도 쓰지 않는 조합을 빼 버립니다**. 그래서 실행 중에 키워드를 바꾸면 빌드에서는 그 조합이 없을 수 있습니다. 랩처럼 실행 중에 바꾸는 스위치를 값으로 만든 또 하나의 까닭입니다.

### 5. 스타일 프리셋: 세 겹으로 덮어쓰기

[그림: 아래에서 위로 쌓인 세 장. ① 머티리얼 파일 값(부위별로 맞춘 값) ② 스타일 프리셋(체크한 값만 덮음) ③ 랩 스위치(끈 것만 0). 맨 위가 화면]

| 순서 | 무엇 | 코드 위치 | 규칙 |
|---|---|---|---|
| ① | 머티리얼 파일 값으로 되돌림 | `LabCharacter.ApplyStyle` 100행 `CopyPropertiesFromMaterial` | 복사본을 `.mat` 원래 값으로 리셋 |
| ② | 프리셋 덮어쓰기 | `LabCharacter.ApplyStyle` 102행 → `StylePreset.ApplyTo` 59–83행 | **Enabled 체크한 숫자**, **Keep이 아닌 기능**만 바꿈 |
| ③ | 랩 스위치 | `LabCharacter.ApplySwitches` 108–119행 | **꺼진 스위치만** 0으로. 켜진 스위치는 아무것도 안 함 |

이 순서는 `ShaderLabController.Apply` (119–129행)에 있습니다.

```csharp
character.ApplyStyle(styles[style]);       // ① + ②
character.ApplySwitches(maps, features);   // ③
```

프리셋의 두 가지 칸 (`StylePreset.cs`)

```csharp
public enum Switch { Keep, On, Off }        // 11행

public struct FloatOverride                 // 14–20행
{
    public bool enabled;    // 체크하면 덮어쓴다
    public float value;
}
```

```csharp
// 85–95행: 덮어쓰기 규칙
static void Set(Material m, string property, FloatOverride o)
{
    if (o.enabled && m.HasFloat(property))
        m.SetFloat(property, o.value);
}

static void Set(Material m, int property, Switch s)
{
    if (s != Switch.Keep && m.HasFloat(property))
        m.SetFloat(property, s == Switch.On ? 1f : 0f);
}
```

**지금 있는 프리셋 3개** (`Settings/Styles/*.asset` 실제 값)

| 칸 | 리얼 (`1_Real`) | 세미리얼 (`2_SemiReal`) | 스타일라이즈드 (`3_Stylized`) |
|---|---|---|---|
| Realism | 1 | - | 0 |
| Shade Softness / Offset | - | - | 0.05 / 0.05 |
| Ambient Strength | - | - | 1.1 |
| Specular / Reflection Strength | - | - | 0.5 / 0.5 |
| Fill Intensity | - | - | 0.5 |
| Rim Intensity / Width / Softness | - | - | 1.5 / 0.3 / 0.05 |
| Outline Width / Opacity / Noise Amount | - | - | 2.6 / 0.95 / 0.35 |
| Fill Light · Rim Light · Shadow Tint · Outline | 모두 **Off** | Keep | 모두 **On** |
| 나머지 기능 | Keep | Keep | Keep |

`-` = Enabled 꺼짐 (머티리얼 값 그대로).

**"끄기만" 규칙 다시 보기**

| 상황 | 결과 | 까닭 |
|---|---|---|
| 리얼 + 먹 아웃라인 스위치 켬 | 선 없음 | ②에서 Off. ③은 켜진 스위치에 아무것도 안 함 |
| 스타일라이즈드 + `O` 키 | 선이 꺼졌다 켜졌다 | ②에서 On → ③이 끌 수 있음 |

### 6. 기능 스위치 하나가 지나가는 길

새 기능 스위치를 만들려면 아래를 **모두** 이어야 합니다. 실습 3에서 그대로 합니다.

| 파일 | 줄 | 까닭 |
|---|---|---|
| `ShaderLabController.cs` | 63 | `Enum.GetValues(typeof(LabFeature))`로 enum을 **전부** 읽어 스위치 표를 만든다 |
| `LabCharacter.cs` | 115–117 | 스위치 표를 `foreach`로 돌며 `ShaderLabProperties.Feature(…)`로 이름을 찾는다 |

## 정리

- 먹 아웃라인 = **같은 메쉬를 노멀 방향으로 부풀려 뒷면만(`Cull Front`) 한 번 더** 그린 것. 윤곽 밖으로 나온 띠만 보인다.
- 굵기는 **화면 픽셀**: 화면에서의 바깥 방향을 구해 `_OutlineWidth` 픽셀만큼 밀고, `* positionCS.w`로 거리 영향을 없앤다.
- `[ToggleUI]` = 값(곱하기, 배리언트 안 늘어남, `SetFloat`만). 키워드 = `#if`(코드가 빠져 빠르지만 배리언트가 곱으로 늘고 `EnableKeyword`도 필요).
- 화면 값 = ① 머티리얼 파일 → ② 프리셋(체크한 것만) → ③ 랩 스위치(끈 것만). 그래서 "프리셋이 끈 기능은 스위치로 못 켠다".
- 기능 스위치 하나 = 쉐이더 3곳(Properties·CBUFFER·쓰는 곳) + `StylePreset.cs` 4곳 + `ShaderLabUI.cs` 1곳. Controller·LabCharacter는 enum을 자동으로 따라온다.

## 확인 질문

1. 카메라를 멀리 빼도 먹 선이 화면에서 같은 굵기로 보인다. 코드의 어느 부분 때문인가?
   - **정답**: 아웃라인 패스의 버텍스 쉐이더(701행)가 정점을 **화면 픽셀 단위**(`_OutlineWidth` × 1픽셀 크기)로 밀고, `* positionCS.w`로 GPU의 원근 나눗셈을 미리 상쇄하기 때문.
2. **리얼** 카드를 고른 뒤 `O`를 눌러도 먹 선이 생기지 않는다. 왜인가?
   - **정답**: 리얼 프리셋이 `outline = Off`로 덮어쓴다(②). 랩 스위치(③)는 **꺼진 스위치만** 0으로 만들고, 켜진 스위치는 아무것도 하지 않는다("끄기만" 규칙).
3. 재질 타입(피부·천)은 `[KeywordEnum]`, 기능 스위치는 `[ToggleUI]`로 만든 까닭은?
   - **정답**: 재질 타입은 머티리얼마다 정해져 잘 안 바뀌고 코드 덩어리가 커서 키워드로 아예 빼는 편이 빠르다. 기능 스위치는 실행 중에 자주 껐다 켜고 8개나 되어 키워드면 배리언트가 2⁸배로 늘고, 값이면 `SetFloat` 한 줄로 바뀐다.

## 자주 막히는 곳

| 증상 | 원인 | 해결 |
|---|---|---|
| 새 카드가 패널에 안 보임 | **Styles** 목록을 플레이 중에 바꿈 (플레이를 멈추면 되돌아감) / 장면 저장 안 함 | 멈춘 상태에서 넣고 `Ctrl + S` |
| 카드 이름이 `Preset` | **Display Name**을 안 바꿈 | `4_InkWash` → **Display Name** |
| 프리셋 값을 바꿨는데 화면 그대로 | 카드를 다시 안 누름 / **Enabled** 체크 안 함 | 카드를 다시 누르기, Enabled 확인 |
| 처음 B가 세미리얼이 아님 | 새 프리셋을 목록 **중간**에 넣음 (**Default Style B** = 1번 칸) | 맨 끝으로 옮기기 |
| Build Test Scene 후 내 프리셋이 목록에서 사라짐 | 장면 메뉴가 장면을 새로 만들며 목록을 3개로 다시 채움 | 에셋은 남아 있음 → 목록에 다시 넣기 |
| 캐릭터가 분홍색, Console `undeclared identifier '_EnableGemGlow'` | CBUFFER에 `half _EnableGemGlow;` 를 안 넣음 | 실습 3-2 |
| 인스펙터에 **Gem Glow** 칸이 없고 속빛이 늘 꺼짐 | `Properties`에 `[ToggleUI]` 줄을 안 넣음 (값이 0) | 실습 3-3 |
| 쉐이더 인스펙터 SRP Batcher가 not compatible | `half _EnableGemGlow;` 를 CBUFFER **밖**에 넣음 | `CBUFFER_START` ~ `CBUFFER_END` 사이로 옮기기 |

| Console `'StylePreset' does not contain a definition for 'gemGlow'` | `public Switch gemGlow;` 안 넣음 | 실습 3-8 |

| 패널에 **보석 속빛** 토글이 없음 | `FeatureInfo` 줄을 안 넣음 (나머지는 동작) | 실습 3-9 |
| 토글을 꺼도 렌즈가 그대로 | 603행에 `* _EnableGemGlow` 를 안 곱함 / 프리셋이 이미 Off | 실습 3-1, 세미리얼 카드로 확인 |
