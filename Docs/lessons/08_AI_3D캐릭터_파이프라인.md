| 항목 | 내용 |
|---|---|
| 수업 시간 | 180분 (시연 25 · 개념 45 · 쉬는 시간 10 · 실습 70 · 정리·과제 20 · 도입 10) |
| 난이도 | ★★★ (장면·인스펙터 작업이 많음. 코드는 읽기 위주) |
| 시작 저장 지점 | `shader-lab-v2` |
| 쓰는 랩 탭 | **애니메이션**, **커스텀** (비교·쉐이더 탭은 확인용) |

## 학습 목표

1. VARCO 3D → Blender 변환 스크립트 → Unity 가져오기 규칙(AssetPostprocessor)으로 이어지는 흐름을 단계별로 말할 수 있다.
2. Humanoid 리그 덕분에 클립 하나를 옷 3벌이 같이 쓰는 까닭과, Playable로 클립을 재생·스크럽하는 방법을 설명한다.
3. `LabCharacter`의 커스텀 칸과 `HandGrip`을 읽고, 장면에 **소품 칸**을 하나 더 만든다.

## 시작 저장 지점

```bash
git switch -c lesson08 shader-lab-v2
git lfs pull
```

### 3. Blender 변환 스크립트 — `Tools/varco_to_unity.py`

> **배치 스크립트**: 화면을 띄우지 않고 명령 한 줄로 여러 파일을 한꺼번에 처리하는 스크립트.

실행 명령 (4행):

```bash
blender -b --factory-startup -P Tools/varco_to_unity.py -- <glb 폴더>
```

| 부분 | 뜻 |
|---|---|
| `-b` | 화면 없이(백그라운드) 실행 |
| `--factory-startup` | 내 Blender 설정을 무시하고 처음 설정으로 |
| `-P 파일` | 이 파이썬 파일을 실행 |
| `-- <glb 폴더>` | `--` 뒤는 스크립트에 넘기는 값. 19행 `SRC = sys.argv[sys.argv.index("--") + 1]` |

| 줄 | 찾을 글자 | 하는 일 |
|---|---|---|
| 20–24 | `PROJ =` | 저장할 곳 = 스크립트 폴더의 위(프로젝트) `Assets/CharacterShaderTest` |
| 26–30 | `CHARS =` | glb 이름 → 저장 이름 표 (`Char_Armor_Rigged` → `Armor` …), 클립 이름 표, 이미시브를 만들 모델 |
| 33–39 | `def load` | 빈 장면에서 glb 하나 열기. VARCO glb에 같이 들어 있는 미리보기용 구(`Icosphere`)는 지움 |
| 46–60 | `def save_textures` | 머티리얼 `material_0`의 Principled BSDF에서 베이스·러프니스(ORM)·노멀 텍스처를 찾아 PNG로 저장 |
| 63–67 | `def export` | FBX로 내보내기 (`add_leaf_bones=False`: 끝 뼈를 더하지 않음) |
| 88–97 | `# ---- 1. 캐릭터·무기` | 메쉬 이름 `Armor_Body` 등, 뼈대 이름 `Armature`로 정리 → FBX + 텍스처 |
| 99–111 | `# ---- 2. 애니메이션` | 메쉬는 지우고 **뼈대만** FBX로. 클립 이름 = `ANIMS` 표 이름 |
| 113–123 | `# ---- 3. 이미시브 맵` | 로브·지팡이 베이스 컬러에서 **밝은 하늘색**(룬 문자·수정)만 남겨 `_Emission.png` |
| 125–132 | `# ---- 4. URP Lit용 메탈릭 맵` | ORM을 URP Lit 규칙으로 다시 담기 |

4번 채널 옮기기 (129–131행):

```python
out[..., 0] = px[..., 2]          # 메탈릭
out[..., 1] = px[..., 0]          # AO (URP Lit Occlusion Map은 G를 읽음)
out[..., 3] = 1.0 - px[..., 1]    # 스무스니스
```

| 텍스처 | R | G | B | A |
|---|---|---|---|---|
| `_ORM.png` (VARCO, glTF 규칙) | AO | 러프니스 | 메탈릭 | — |
| `_MetallicSmoothness.png` (URP Lit용) | 메탈릭 | AO | — | 스무스니스 (= 1 − 러프니스) |

새 쉐이더는 ORM 한 장을 그대로 씁니다. 같은 텍스처를 메탈릭(B)·러프니스(G)·AO(R) 세 칸에 넣고 채널만 다르게 고릅니다 (`Editor/SemiRealInkTestSetup.cs` 179–194행 `AssignOrmMap`, 5차시 내용).

### 4. 가져오기 규칙 — `Editor/VarcoAssetImporter.cs`

`AssetPostprocessor`를 물려받은 클래스는 따로 붙이지 않아도 Unity가 가져오기 때마다 부릅니다. 경로로 "VARCO 파일인가"를 먼저 거릅니다(15, 46, 65행 `StartsWith`).

| 줄 | 함수 | 규칙 |
|---|---|---|
| 22 | `OnPreprocessModel` | 머티리얼은 만들지 않음 (`ModelImporterMaterialImportMode.None`). 장면 메뉴가 만든다 |
| 23–29 | 〃 | 크기: 캐릭터 `1.7` (VARCO 모델은 키 1m로 나옴), `Sword` 1, `Bow` 1.15, `Staff` 1.6 |
| 31–36 | 〃 | 무기: 뼈대·애니메이션 없음 |
| 38–40 | 〃 | 캐릭터·클립: `Human`, Avatar는 `CreateFromThisModel`, 애니메이션은 `Animations/` 폴더만 가져옴 |
| 53–58 | `OnPreprocessAnimation` | 클립 이름 = 파일 이름. `Idle`·`Walk`·`Run`만 Loop Time. 루트 높이(Y)·회전은 고정 |
| 68–71 | `OnPreprocessTexture` | `_Normal.png` → Normal Map. `_ORM.png`·`_MetallicSmoothness.png` → sRGB 끔 |

```csharp
// VarcoAssetImporter.cs 38–40행 (찾을 글자: "ModelImporterAnimationType.Human")
importer.animationType = ModelImporterAnimationType.Human;
importer.avatarSetup = ModelImporterAvatarSetup.CreateFromThisModel;
importer.importAnimation = animation;
```

> **sRGB**: 사람 눈에 맞춘 색 저장 방식. 색 그림(베이스·이미시브)은 켜고, 숫자를 담은 데이터 텍스처(ORM·노멀·마스크)는 끈다. 켜 두면 값이 휘어서 금속·거칠기가 틀어진다.

### 6. Playable로 재생하기 — `Scripts/AnimationTester.cs`

> **PlayableGraph**: 애니메이션 재료(클립)와 출력(Animator)을 선으로 잇는 작은 그래프. 코드로 만들고 지운다.

Animator Controller(상태 그림)를 만들지 않고, 클립 하나를 바로 Animator에 연결합니다. 그래서 일시정지·속도·시간 이동이 자유롭습니다. 캐릭터(A·B)마다 그래프를 하나씩 만듭니다.

```csharp
// AnimationTester.cs Play() 안, 44–49행 (찾을 글자: "PlayableGraph.Create")
t.graph = PlayableGraph.Create($"ShaderLab Anim ({t.animator.name})");
t.graph.SetTimeUpdateMode(DirectorUpdateMode.GameTime);
t.clipPlayable = AnimationClipPlayable.Create(t.graph, clip);
var output = AnimationPlayableOutput.Create(t.graph, "Animation", t.animator);
output.SetSourcePlayable(t.clipPlayable);
t.graph.Play();
```

| 랩 버튼 (`ShaderLabUI.cs` 471–529행) | 부르는 함수 | 줄 | 하는 일 |
|---|---|---|---|
| **클립** 드롭다운 | `Play(clip)` | 36–53 | 그래프를 새로 만들고 재생 |
| **재생** / **일시정지** | `SetPlaying()` | 73–77 | 속도를 0으로 (그래프는 그대로) |
| **◀ 1프레임** / **1프레임 ▶** | `StepFrames()` | 108–115 | 일시정지 후 `1 / Clip.frameRate`초 이동 (frameRate가 없으면 30) |
| **시간** 슬라이더 | `Seek()` | 93–105 | `SetTime` 후 `graph.Evaluate()` → 멈춘 채로 그 자세가 바로 보임 |
| **속도** (0~2) | `SetSpeed()` | 79–90 | `clipPlayable.SetSpeed` |
| **반복 재생** | `Loop` | 23, 131–145 | `Tick()`이 끝에 닿으면 처음으로 되돌림 |
| **루트 모션 (제자리에서 벗어나 이동)** | `SetRootMotion()` | 117–128 | `animator.applyRootMotion`. 끄면 처음 자리로 |
| **멈춤 (기본 자세)** | `Stop()` | 56–71 | 그래프 지우고 `Rebind()` → 바인드 포즈 |

- 랩에서는 `Tick()`이 반복을 직접 처리하므로 **반복 재생**을 켜면 10개 모두 반복됩니다. 가져오기 규칙의 Loop Time(`Idle`·`Walk`·`Run`)은 게임에서 Animator Controller로 쓸 때 의미가 있습니다.
- 옷을 바꾸면 Animator(뼈대)가 바뀝니다. 그래서 `ShaderLabController.SelectSlotOption()`(300–326행)은 지금 클립·시간·속도를 기억 → `AnimationTester`를 새로 만들기 → 같은 시간에서 이어 재생합니다. 시연 15번에서 동작이 안 끊긴 까닭입니다.

### 7. 커스텀 칸 — `LabCharacter.cs`

캐릭터 하나 = 옷 4벌 + 무기 3개가 **모두 자식으로 들어 있고**, 칸마다 하나만 켭니다.

```csharp
// LabCharacter.cs 19–27행 (찾을 글자: "class CustomizationSlot")
[Serializable]
public class CustomizationSlot
{
    public string name;
    [Tooltip("비워 둘 수 있는 칸이면 '없음' 선택지가 생긴다 (무기 등)")]
    public bool allowNone;
    public List<GameObject> options = new();
    public int defaultIndex;
}
```

| 칸 필드 | 인스펙터 이름 | 뜻 |
|---|---|---|
| `name` | Name | 칸 이름 = 커스텀 탭 머리글. **A·B가 같은 이름**이어야 같이 바뀐다 |
| `allowNone` | Allow None | 켜면 **없음** 버튼이 생긴다 |
| `options` | Options | 후보 오브젝트. 버튼 글자 = 오브젝트 이름 |
| `defaultIndex` | Default Index | 처음 고를 번호. `-1` = 없음 (Allow None 칸만) |

장면 메뉴가 만드는 칸 두 개 (`SemiRealInkTestSetup.cs`):

| 줄 | 칸 | 후보 | 설정 |
|---|---|---|---|
| 756, 765–778 | `옷` | 갑옷 (VARCO) · 한복 (VARCO) · 마법사 로브 (VARCO) · 조선 스팀펑크 (FinalPlayer) | `defaultIndex = 0` |
| 757, 782–788 | `무기` | 검 · 활 · 지팡이 | `allowNone = true`, `defaultIndex = -1` |

버튼을 누르면 이렇게 흐릅니다.

| 순서 | 위치 | 하는 일 |
|---|---|---|
| 1 | `ShaderLabUI.BuildCustomizeTab()` 531–558행 | **B 캐릭터**의 칸 목록으로 버튼을 만든다 (`Allow None`이면 **없음** 먼저) |
| 2 | `ShaderLabController.SelectSlotOption()` 300–326행 | A·B **두 캐릭터 모두**에 같은 칸 이름·번호를 보낸다 |
| 3 | `LabCharacter.SelectOption()` 136–149행 | 고른 후보만 `SetActive(true)` |
| 4 | `LabCharacter.AttachGrips()` 153–173행 | `HandGrip`이 붙은 후보를 지금 옷의 뼈로 옮긴다 |
| 5 | `ShaderLabController.RefreshCharacters()` | 새로 켜진 것에도 스타일·스위치를 다시 건다 |

**머티리얼은 따로 등록**: 스타일·원본 바꾸기는 `LabCharacter`의 **Renderers** 목록(렌더러마다 `Lit`·`Lab` 머티리얼 짝)에 있는 것만 바꿉니다(94–104행 `UseLabShader`). 장면 메뉴는 옷·무기의 모든 렌더러를 이 목록에 넣습니다(796–804행). **새 소품을 만들면 이 목록에도 넣어야 합니다.**

### 8. 무기를 손에 쥐기 — `HandGrip.cs`

```csharp
// HandGrip.cs 5–11행
public class HandGrip : MonoBehaviour
{
    public HumanBodyBones bone = HumanBodyBones.RightHand;
    public Vector3 localPosition;
    public Quaternion localRotation = Quaternion.identity;
    public Vector3 localScale = Vector3.one;
}
```

- `HandGrip` = "어느 뼈(`bone`)에, 그 뼈 기준으로 어디(`localPosition`)·어떤 방향(`localRotation`)·크기(`localScale`)로 붙일지" 적은 쪽지입니다. 기본 뼈는 오른손.
- `HumanBodyBones`는 Humanoid 부위 이름 목록입니다. 오른손뿐 아니라 `LeftHand`, `Head` 등 어느 부위든 됩니다.
- 쪽지 값은 장면 메뉴가 **갑옷 캐릭터의 T 포즈**에서 계산해 둡니다 (`CreateWeapon` 834–868행). 손잡이 = 세운 무기 위에서 `gripFromTop` 비율 아래, 손바닥 = 손목 뼈에서 손가락 쪽으로 0.07m (857행).
- 실행 중에는 `AttachGrips()`가 쪽지대로 붙입니다.

```csharp
// LabCharacter.cs AttachGrips() 안, 164–171행 (찾을 글자: "GetBoneTransform(grip.bone)")
var hand = animator != null && animator.isHuman ? animator.GetBoneTransform(grip.bone) : null;
// Humanoid 뼈대가 없는 모델(예: FinalPlayer)은 쥘 손이 없으니 무기를 숨긴다
option.SetActive(hand != null);
if (hand == null)
    continue;
option.transform.SetParent(hand, false);
option.transform.SetLocalPositionAndRotation(grip.localPosition, grip.localRotation);
option.transform.localScale = grip.localScale;
```

- `animator`는 `ActiveAnimator`(35–44행) = **지금 켜진 옷**의 Humanoid Animator입니다. 옷을 바꾸면 새 옷의 손 뼈를 찾습니다.
- 손 뼈의 부모 옷이 꺼지면 무기도 같이 안 보이므로, 옷을 바꿀 때마다 **새 옷의 뼈로 옮기는 것**이 핵심입니다.
- T 포즈에서 계산한 근사치라 동작에 따라 손에서 조금 떠 보일 수 있습니다 (README 알려진 한계).

- 파이프라인 = VARCO 3D(glb) → Blender 배치 스크립트(FBX·PNG, 이미시브·메탈릭 맵 만들기) → `AssetPostprocessor`(가져오기 규칙) → 장면 메뉴(머티리얼·칸·클립).
- 가져오기 규칙을 코드로 두면, 파일을 다시 넣어도 **설정이 늘 같다** (Humanoid·1.7배·sRGB 끔).
- Humanoid 클립은 Avatar만 있으면 다른 모델에도 그대로 재생된다 → 클립 10개를 옷 3벌이 같이 쓴다.
- `AnimationTester`는 Playable로 클립 하나를 A·B에 같이 재생한다. 옷을 바꾸면 새로 만들어 같은 시간에서 잇는다.
- 커스텀 칸 = 이름 + 후보 + 없음 허용 + 처음 번호. **A·B 둘 다** 같은 이름으로, 새 렌더러는 **Renderers**에도.
- `HandGrip` = 뼈 + 그 뼈 기준 자세. `AttachGrips()`가 지금 옷의 뼈로 옮겨 붙인다.

## 과제

**과제 1. 동작 × 스타일 비교표** — 동작 3개 × 스타일 3개 = 9칸을 캡처하고 한 줄씩 쓴다.

- 동작: `Walk` 1개 + 무기 동작 1개(`SwordSlash`·`ShootBow`·`StaffSpin` 중, 맞는 무기를 들고) + 자유 1개
- 스타일: **리얼 · 세미리얼 · 스타일라이즈드** (**B만 (4)** 보기, **쉐이더** 탭 스타일 카드로 바꿈)
- 같은 칸끼리는 **같은 시간**: **일시정지** 후 시간 글자(`…s`)를 맞추고, **처음 시점 (F)** 으로 시점을 맞춘다

| 동작 \ 스타일 | 리얼 | 세미리얼 | 스타일라이즈드 |
|---|---|---|---|
| `Walk` (시간: ___s) | | | |
| ______ (시간: ___s) | | | |
| ______ (시간: ___s) | | | |

칸마다 "명암 경계·먹 선·역광 테두리 중 무엇이 동작 중에 눈에 띄게 바뀌었나"를 한 줄.

**과제 2. 소품 칸 완성** — 실습 5의 **소품** 칸에 후보를 하나 더 넣어 **없음 / 등불 / (내 소품)** 으로 만든다.

- 예: `모자` (Cylinder, **Bone** = Head) 또는 `책` (Cube, **Bone** = Left Hand)
- 후보를 넣을 때마다: A·B 양쪽 자식 오브젝트 + 레이어 + 머티리얼 + HandGrip + **Slots → 소품 → Options** 에 추가 + **Renderers** 에 추가
- Options 순서는 A·B가 같아야 한다 (버튼 번호로 고르기 때문)
- 자세는 실습 4의 5번 방법(플레이 중 맞추고 숫자 적기)으로 맞춘다
- 제출: 옷 3벌(갑옷·한복·로브) × 내 소품 캡처 3장 + HandGrip 값 표

| 제출물 | 채점 기준 | 배점 |
|---|---|---|
| 과제 1 캡처 9장 + 표 | 같은 행은 같은 시간·시점, 스타일 이름이 드러난다 | 25 |
| 과제 1 설명 9줄 | "움직일 때" 보이는 차이를 구체적으로 적었다 | 20 |
| 과제 2 커스텀 탭 캡처 | **소품** 머리글에 버튼 3개(없음 포함), A·B 양쪽에 같은 소품이 보인다 | 20 |
| 과제 2 옷 3벌 캡처 | 옷을 바꿔도 소품이 같은 뼈를 따라간다 | 15 |

## 확인 질문

1. 클립 10개는 갑옷 캐릭터 뼈대로 만들었다. 그런데 한복·로브에서도 같은 클립이 재생되는 까닭은?
   - **정답**: 세 모델 모두 Humanoid로 가져와 Avatar가 있고(`VarcoAssetImporter.cs` 38–39행), Humanoid 클립은 특정 뼈가 아니라 사람 부위 기준으로 저장되기 때문. 뼈 이름이 같아 자동 매핑도 된다.
2. 옷을 갑옷에서 한복으로 바꾸면 손에 든 검도 한복의 손으로 옮겨 간다. 어떤 코드가 어떻게 하는가?
   - **정답**: `LabCharacter.SelectOption()` 끝에서 `AttachGrips()`가 불린다. 지금 켜진 옷의 `ActiveAnimator.GetBoneTransform(grip.bone)`으로 손 뼈를 찾아 `SetParent` 하고 `HandGrip`의 위치·회전·크기를 넣는다.
3. 장면에 소품을 B 캐릭터에만 넣고 Slots에 칸을 만들었더니, 커스텀 탭에 버튼은 생기는데 A 쪽에는 소품이 안 보인다. 왜일까?
   - **정답**: 버튼은 B 캐릭터의 칸 목록으로 만들고(`ShaderLabUI.BuildCustomizeTab`), 선택은 A·B 각각의 `SelectOption(칸 이름, 번호)`로 보낸다. A에 같은 이름의 칸이 없으면 `SelectOption`이 칸을 못 찾고 그냥 돌아간다(138–140행).
