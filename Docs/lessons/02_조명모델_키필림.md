## 학습 목표

1. 노멀과 빛 방향의 내적(N·L)으로 명암이 생기는 원리(람버트)를 말하고, 2단 명암과의 차이를 `Realism` 값으로 보여 줄 수 있다.
2. 한 픽셀의 색이 "키 라이트(+그림자) + 환경광(+그늘 색) + 필 + 림"으로 더해진다는 것을 쉐이더 코드에서 찾을 수 있다.
3. 쉐이더 `Properties`와 `CBUFFER`에 값 하나를 더해 림 라이트 색을 조절하는 기능을 직접 만든다.

## 시연 순서

### A. 준비 — 빛을 보기 좋은 무대 (3분)

1. `CharacterShaderTest.unity`를 열고 ▶ 플레이.
2. **환경** 탭 → **중립 스튜디오** 카드. 카드 설명을 읽어 준다: "쉐이더 자체를 평가할 때 쓰는 기준 환경".
3. **비교** 탭 → **A (왼쪽)** = `원본 (URP Lit)`, **B (오른쪽)** = `세미리얼`, 비교 방식 **와이프 (1)**.

### B. 색을 빼고 빛만 보기 (5분)

4. **맵·보기** 탭 → 디버그 보기 **빛만 (회색 점토)**. "캐릭터를 회색 찰흙으로 만들었다. 이제 보이는 것은 **빛과 그림자뿐**"이라고 말한다.
   - A(원본 URP Lit)는 그대로다. 디버그 보기는 새 쉐이더에만 걸린다.
5. "텍스처 맵 켜고 끄기"에서 **노멀 맵**을 끈다 → 얼굴·옷의 잔주름이 사라진다 → 다시 켠다.
6. 디버그 보기 **노멀 (방향 색)** → "표면이 향하는 방향을 색으로 칠한 것"만 보여 주고 다시 **빛만 (회색 점토)**.

![노멀 보기 (B 쪽)](../images/lab_debug_normal.png)

### C. 키 라이트 방향 바꾸기 (7분)

7. **조명** 탭 → "조명 프리셋" 카드를 차례로 누른다: **정면광 → 45° 키 라이트 → 측면광 → 역광 → 탑라이트**.
   - 볼 것: 밝은 쪽·어두운 쪽 경계가 어디로 가는지, 바닥 그림자가 어디로 눕는지.
8. **측면광**에서 "햇빛 돌리기"의 **방향 (도)** 슬라이더를 천천히 끈다. 명암 경계가 몸을 따라 돈다.

### D. 실사 명암 ↔ 2단 명암 (4분)

9. **비교** 탭 → **A (왼쪽)** = `리얼`, **B (오른쪽)** = `스타일라이즈드`. (A도 새 쉐이더라 이제 양쪽 다 빛만 보기다.)
10. 와이프 선을 끌며 비교: A는 밝음이 **부드럽게** 줄고, B의 옷·소품은 밝음/어둠 **두 칸**으로 딱 나뉜다. (얼굴·몸 피부는 SSS 계산이 명암을 섞어서 B에서도 덜 또렷하다 — 3차시)

### E. 필·림·그늘 색 — 카메라를 따라오는 빛 (6분)

11. **비교** 탭 → **B (오른쪽)** = `세미리얼`, 키보드 `4`(B만).
12. **쉐이더** 탭 → "기능 켜고 끄기"에서 **보조광 (필 라이트)**, **역광 (림 라이트)**, **그늘 색**을 하나씩 껐다 켠다.
13. 마우스 왼쪽 드래그로 캐릭터를 돌려 본다(실제로는 카메라가 캐릭터 둘레를 돈다).
    - 볼 것: 햇빛 명암은 몸 위에서 자리를 옮기는데, **림 테두리는 늘 화면 오른쪽 위**, 필은 늘 화면 왼쪽에서 온다.
14. **조명** 탭 → **3점 조명 + 포인트**. "이건 장면에 **진짜 포인트 라이트 2개**를 켠 것. 방금 본 필·림은 쉐이더 안의 **계산으로 만든 빛**"이라고 대비시킨다.
15. 디버그 보기를 **보통 화면**으로, 조명은 **환경 기본**으로 돌린다.

[그림: 같은 캐릭터를 카메라 세 각도에서 캡처. 햇빛 그림자 위치는 바뀌고, 림 테두리는 세 장 모두 화면 오른쪽 위에 있는 모습]

## 개념 설명

### 1. 용어 여덟 개

| 용어 | 한 줄 풀이 | 이 프로젝트에서 |
|---|---|---|
| 노멀 (Normal) | 표면이 바라보는 방향 화살표. 길이 1 | 쉐이더 변수 `N` |
| 노멀 맵 (Normal Map) | 노멀 방향을 픽셀마다 살짝 비틀어 잔주름을 그려 넣는 텍스처 | `_BumpMap` ("Normal Map") |
| 내적 (dot) | 두 방향이 얼마나 같은 쪽을 보는지 숫자로: 같으면 1, 직각이면 0, 반대면 −1 | `dot(N, L)` |
| 람버트 (Lambert) | "밝기 = N·L" 이라는 가장 기본 명암 규칙 | `ShadeTerm()` 안 `lambert` |
| 키 라이트 (Key) | 장면의 주인공 빛. 그림자를 만든다 | 장면의 `Sun` (디렉셔널 라이트) |
| 필 라이트 (Fill) | 어두운 쪽을 살짝 밝히는 보조광 | 쉐이더 안 계산 (`_FillDirection`) |
| 림 라이트 (Rim) | 뒤에서 와서 윤곽에 밝은 테두리를 만드는 빛 | 쉐이더 안 계산 (`_RimDirection`) |
| 환경광 (Ambient) | 하늘·땅에서 사방으로 오는 약한 빛 | `SampleSH(Nd)` (SH = 환경광을 몇 개 숫자로 줄여 담은 것) |

> **카메라 공간(View Space)**: 카메라를 기준으로 잰 방향. x = 화면 오른쪽, y = 화면 위, z = +면 카메라 쪽(앞), −면 캐릭터 뒤쪽.

### 2. 노멀과 노멀 맵 (짧게)

빛 계산은 모두 **노멀**에서 시작합니다. 노멀은 두 단계로 만듭니다.

| 단계 | 하는 일 | 파일·줄 (`SemiRealInk.shader`) | 찾을 글자 |
|---|---|---|---|
| ① 버텍스 노멀 | 모델 꼭짓점에 저장된 방향을 월드 방향으로 | 323, 327 | `GetVertexNormalInputs` |
| ② 노멀 맵 읽기 | 텍스처에서 "면 기준으로 얼마나 비틀지" 읽기. 끄면 `(0, 0, 1)` = 비틀지 않음 | 250–256 | `half3 SampleNormalTS` |
| ③ 합치기 | ①의 면 위에 ②를 얹어 최종 `N` | 435–442 | `// 노멀맵 (꺼져 있으면 평평한 면)` |

```hlsl
// 250–256행: 노멀맵 (탄젠트 공간): 맵을 끄면 평평한 면 (0, 0, 1)
half3 SampleNormalTS(float2 uv)
{
    if (_UseNormalMap < 0.5h)
        return half3(0, 0, 1);
    return UnpackNormalScale(SAMPLE_TEXTURE2D(_BumpMap, sampler_BumpMap, uv), _BumpScale);
}
```

> **탄젠트 공간(Tangent Space)**: 표면 한 점에 붙인 작은 좌표. z = 표면 바깥쪽. 그래서 비틀림이 없는 노멀 맵 픽셀은 `(0, 0, 1)` → 색으로 `(0.5, 0.5, 1)` 연보라가 됩니다.

| Properties 칸 | 줄 | 인스펙터 이름 | 뜻 |
|---|---|---|---|
| `_BumpMap` | 21 | Normal Map | 노멀 맵 텍스처 |
| `_BumpScale` | 22 | Normal Strength | 비틀림 세기 (0 = 평평, 2 = 두 배) |
| `_UseNormalMap` | 23 | Use Normal Map | 랩의 **노멀 맵** 스위치가 이 값을 0으로 만든다 |

- 디버그 보기 **노멀 (방향 색)** = 469행 `return half4(N * 0.5h + 0.5h, 1);`. 방향(−1~1)을 색(0~1)으로 옮긴 것.
- FinalPlayer는 베이스·노멀 맵만 있습니다(`Textures/FinalPlayer/*Normal*.png`). 메탈릭·러프니스·AO 맵은 5차시(v2 캐릭터)에서 다룹니다.

![맵 스위치: 베이스·노멀 끔](../images/lab_maps_toggle.png)

### 3. N·L — 람버트 명암

빛이 표면을 **정면으로** 때리면 밝고, **비스듬히** 때리면 같은 빛이 넓게 퍼져 어둡습니다. 이것을 내적 하나로 계산합니다.

[그림: 공 하나. 위쪽에서 빛 화살표 L. 공 표면 세 곳에 노멀 화살표 N — 꼭대기(N·L = 1, 가장 밝음), 옆(N·L = 0, 경계), 아래(N·L < 0, 빛 못 받음)]

| N과 L 사이 각도 | N·L | 밝기 `saturate(N·L)` |
|---|---|---|
| 0° (빛을 정면으로 봄) | 1 | 1 |
| 60° | 0.5 | 0.5 |
| 90° (빛과 나란함) | 0 | 0 |
| 120° (빛 반대쪽) | −0.5 | 0 (음수는 0으로 자름) |

> **saturate**: 0보다 작으면 0, 1보다 크면 1로 자르는 함수.

```hlsl
// 387행 — EvaluateLight() 안 (찾을 글자: "half NdotL = dot(")
half NdotL = dot(Nd, light.direction);
```

`light.direction`은 표면에서 **빛 쪽으로** 향하는 방향입니다. `Nd`는 확산광(물체 색이 퍼지는 빛)용 노멀로, 보통은 `N`과 같습니다(피부만 흐리게 씀 — 3차시).

### 4. Realism — 실사 명암과 2단 명암 섞기

```hlsl
// 377–382행 (찾을 글자: "half ShadeTerm")
half ShadeTerm(half NdotL)
{
    half lambert = saturate(NdotL);
    half stylized = smoothstep(_ShadeOffset - _ShadeSoftness, _ShadeOffset + _ShadeSoftness, NdotL);
    return lerp(stylized, lambert, _Realism);
}
```

> **smoothstep(a, b, x)**: x가 a보다 작으면 0, b보다 크면 1, 그 사이는 부드럽게 0→1.
> **lerp(a, b, t)**: a와 b를 t 비율로 섞기. t = 0이면 a, 1이면 b.

| 값 | 줄 | 인스펙터 이름 | 하는 일 |
|---|---|---|---|
| `_Realism` | 106 | Realism (0 Stylized, 1 Real) | 0 = 2단 명암만, 1 = 람버트만 |
| `_ShadeSoftness` | 107 | Shade Edge Softness | 2단 경계의 폭. 작을수록 칼같이 또렷 |
| `_ShadeOffset` | 108 | Shade Edge Offset | 경계 위치. + 이면 어두운 쪽이 넓어짐 |

[그림: 가로축 N·L(−1~1), 세로축 밝기(0~1) 그래프. 선 세 개 — 람버트(0에서 꺾여 비스듬히 오르는 선), 2단(Softness 0.35, 완만한 S자), 2단(Softness 0.05, 거의 계단)]

스타일 프리셋이 이 값을 어떻게 바꾸는지 (`Editor/SemiRealInkTestSetup.cs` `CreateStylePresets`, 295–335행):

| 스타일 | Realism | Shade Edge Softness | Shade Edge Offset |
|---|---|---|---|
| 리얼 | 1 | (머티리얼 값) | (머티리얼 값) |
| 세미리얼 | 머티리얼 값 그대로 (피부 1, 그 밖 0.5) | 0.35 | 0 |
| 스타일라이즈드 | 0 | 0.05 | 0.05 |

> 피부(`Material Type = Skin`)는 예외입니다. 395행 `lerp(ShadeTerm(NdotL).xxx, wrapped, max(_Realism, 0.6h))` 때문에 `Realism`이 0이어도 피부 랩 명암이 60% 이상 섞입니다. 자세한 것은 3차시.

### 5. 그림자

| 재료 | 위치 | 하는 일 |
|---|---|---|
| 그림자 드리우기 패스 | 736행 `Name "ShadowCaster"` | 캐릭터를 해 쪽에서 본 깊이 그림(그림자 맵)에 그려 넣는다 |
| 메인 라이트 + 그림자 읽기 | 538–539행 (찾을 글자: `GetMainLight(shadowCoord`) | 이 픽셀이 그림자 맵에 가려졌는지 → `light.shadowAttenuation` (0 = 그림자 속, 1 = 빛) |
| 명암에 곱하기 | 409행 | `shade3 = (ShadeTerm(NdotL) * light.shadowAttenuation * light.distanceAttenuation).xxx;` |
| 그림자 진하기 | `ShaderLabController.cs` 220행 `sun.shadowStrength = env.shadowStrength;` | 환경 프리셋마다 다름 (중립 스튜디오 0.7, 맑은 한낮 0.9) |

> **그림자 맵(Shadow Map)**: 빛 위치에서 장면을 찍어 "빛이 처음 닿는 거리"를 기록한 텍스처. 그보다 멀면 가려진 것.

정리하면 **명암(N·L)** 은 "표면이 빛을 등졌나", **그림자** 는 "다른 물체가 빛을 막았나"입니다. 둘 다 곱해져서 `keyShade`(키 라이트를 얼마나 받았나)가 됩니다.

### 6. 환경광과 그늘 색

키 라이트만 있으면 그늘이 새까맣습니다. 그래서 환경광을 더합니다.

```hlsl
// 544–547행 (찾을 글자: "half3 ambient = SampleSH")
half3 ambient = SampleSH(Nd) * _AmbientStrength * aoIndirect;
half3 shadowTint = lerp(half3(1, 1, 1), _ShadowTint.rgb, _EnableShadowTint);
color += brdf.diffuse * ambient * lerp(shadowTint, half3(1, 1, 1), keyShade);
```

| 부분 | 뜻 |
|---|---|
| `SampleSH(Nd)` | 노멀 방향의 환경광 색. 위를 보면 하늘색, 아래를 보면 땅색 |
| `_AmbientStrength` | "Ambient Strength" (124행). 환경광 세기 |
| `lerp(shadowTint, 1, keyShade)` | 키 라이트를 **못 받은 곳**(`keyShade` ≈ 0)일수록 환경광에 `Shadow Tint` 색을 곱한다 |

- 환경광 색은 환경 프리셋이 정합니다: `ShaderLabController.cs` 147–150행 (`RenderSettings.ambientMode = AmbientMode.Trilight;` 하늘·지평선·땅 세 색).
- `_ShadowTint` 기본값 `(0.55, 0.63, 0.8)` = 푸르스름. "얼어붙은 세상"의 차가운 그늘(쉐이더 12행 주석).
- `Shadow Tint`라는 이름이 **두 개** 있습니다: 53행 `_EnableShadowTint`(Features 체크박스, 랩의 **그늘 색** 스위치)와 109행 `_ShadowTint`(Key Light 머리글 아래 색).
- 그림자 속도 `keyShade`가 0이라 그늘 색을 받습니다.

### 7. 카메라 기준 필·림

필과 림은 장면에 **라이트 오브젝트가 없습니다**. 쉐이더가 "카메라 기준 방향"을 정해 두고 직접 계산합니다.

```hlsl
// 418–421행: 카메라 공간 방향 → 월드 방향
half3 CameraSpaceDirToWorld(float3 dirVS)
{
    return SafeNormalize(mul((float3x3)UNITY_MATRIX_I_V, dirVS));
}
```

`UNITY_MATRIX_I_V`는 "카메라 공간 → 월드"로 바꾸는 행렬입니다. 카메라가 돌면 이 행렬도 같이 돌아서, 빛이 **카메라에 붙어 다닙니다**.

**필 라이트** (576–582행, 찾을 글자: `// ---- 필 라이트`)

```hlsl
half3 fillDir = CameraSpaceDirToWorld(_FillDirection.xyz);
half fillWrap = saturate(dot(Nd, fillDir) * 0.5h + 0.5h);
half3 fillLight = _FillColor.rgb * _FillIntensity * _EnableFillLight;
color += brdf.diffuse * fillLight * (fillWrap * fillWrap);
```

- `dot * 0.5 + 0.5`: N·L(−1~1)을 0~1로 옮긴다. 빛 반대쪽도 0이 아니라 **조금 밝다** → 부드러운 보조광 (하프 람버트라고 부른다).
- 그림자를 곱하지 않는다 → 그림자 없음.
- 582행: 금속·보석에는 필 방향의 두 번째 하이라이트도 더한다.

**림 라이트** (584–594행, 찾을 글자: `// ---- 림 라이트`)

```hlsl
half3 rimDir = CameraSpaceDirToWorld(_RimDirection.xyz);
half rimMask = smoothstep(1.0h - _RimWidth, 1.0h - _RimWidth + _RimSoftness, 1.0h - NdotV);
half rimFacing = saturate(dot(N, rimDir) * 0.5h + 0.5h);
half3 rimTint = lerp(albedo, half3(1, 1, 1), 0.5h);
// (591–593행: 피부면 rimTint를 살짝 붉게)
color += rimTint * _RimColor.rgb * rimMask * rimFacing * _RimIntensity * _EnableRimLight;
```

| 부분 | 뜻 |
|---|---|
| `1 - NdotV` | 표면이 카메라를 **등질수록** 1 → 윤곽(가장자리)에서만 큼 |
| `rimMask` | 가장자리 띠. `Rim Width`(폭)·`Rim Softness`(번짐) |
| `rimFacing` | 림 방향을 향한 쪽 윤곽만 밝게 |
| `rimTint` | **바탕색(albedo)과 흰색을 반반 섞은 색**. 그래서 파란 옷의 림은 파르스름, 빨간 안감의 림은 불그스름 |

> **albedo**: 빛을 받기 전 표면 고유의 색(베이스 컬러).

| 값 | 줄 | 인스펙터 이름 | 기본값 | 카메라 기준 뜻 |
|---|---|---|---|---|

| `_FillIntensity` | 113 | Fill Intensity | 0.35 | |

### 실습 5. 림 색 순도 값 추가 (25분)

지금 림 색은 `rimTint = lerp(albedo, 흰색, 0.5)`라서 **바탕색이 반쯤 섞입니다**. 파란 옷에 주황 림을 주면 탁해집니다. **Rim Color Purity**(림 색 순도) 값을 더해서, 1이면 **Rim Color 그대로** 나오게 만듭니다.

## 정리

- 명암 = **N·L**. 노멀은 버텍스 노멀(큰 모양) + 노멀 맵(잔주름).
- `ShadeTerm()` 은 람버트와 2단 명암을 `Realism`으로 섞는다. 2단 경계는 `Shade Edge Softness`(폭)·`Shade Edge Offset`(위치).
- 그림자는 `light.shadowAttenuation`으로 명암에 곱해진다. 그림자를 드리우는 일은 `ShadowCaster` 패스.
- 그늘은 환경광이 채우고, 키 라이트를 못 받은 곳일수록 `Shadow Tint` 색이 입혀진다.
- 필·림은 **카메라 기준 방향**을 쓰는 쉐이더 안의 빛 → 카메라를 돌려도 늘 같은 쪽. 조명 탭은 장면의 `Sun`만 바꾼다.
- 머티리얼 값을 하나 더하려면 **Properties + CBUFFER + 쓰는 곳** 세 군데를 고친다.

## 확인 질문

1. 카메라를 돌려도 림 테두리가 늘 화면 오른쪽 위에 생기는 이유는?
   - **정답**: `_RimDirection`이 **카메라 공간** 방향이고, `CameraSpaceDirToWorld()`가 `UNITY_MATRIX_I_V`(카메라 → 월드 행렬)로 매번 바꿔 쓰기 때문. 장면 라이트가 아니라 카메라에 붙은 계산이다.
2. `Realism` = 0, `Shade Edge Softness` = 0.05, `Shade Edge Offset` = 0 이면 명암이 어떻게 보이고, `Realism` = 1이면 어떻게 바뀌나?
   - **정답**: 0이면 `smoothstep(−0.05, 0.05, N·L)` → N·L = 0 근처에서 칼같이 갈리는 2단 명암. 1이면 `saturate(N·L)` 람버트 → 빛을 등질수록 서서히 어두워진다.
3. **그늘 색** 스위치를 끄면 키 라이트를 받는 밝은 쪽도 색이 바뀌나?
   - **정답**: 거의 안 바뀐다. `Shadow Tint`는 **환경광**에만 곱해지고, `lerp(shadowTint, 1, keyShade)`라서 키 라이트를 받는 곳(`keyShade` ≈ 1)은 흰색(=변화 없음)에 가깝다. 바뀌는 곳은 그늘과 그림자 속.

## 자주 막히는 곳

| 증상 | 원인 | 해결 |
|---|---|---|
| 쉐이더 저장 후 캐릭터·공이 분홍색 | 쉐이더 컴파일 오류 | Console의 빨간 줄을 더블클릭. 세미콜론 `;`, 괄호 짝 확인 |
| Console에 `undeclared identifier '_RimColorPurity'` | ② CBUFFER 줄을 빠뜨렸거나 이름 철자가 다름 | 227행 아래 `half _RimColorPurity;` 확인. Properties·CBUFFER·쓰는 곳의 이름 세 개가 **글자까지 같아야** 함 |
| 쉐이더 인스펙터 SRP Batcher가 `not compatible` | 새 값을 `CBUFFER_END` 밖(예: 157행 `_ShaderLabDebugView` 옆)에 선언 | `CBUFFER_START(UnityPerMaterial)` ~ `CBUFFER_END` 안으로 옮긴다 |
| 인스펙터에 **Rim Color Purity** 칸이 없음 | ③ Properties 줄을 빠뜨림 | 121행 아래에 넣기 |
| 줄 번호가 교안과 안 맞음 | 위쪽을 먼저 고쳐 줄이 밀림 | **찾을 글자**로 찾는다. 다음부터는 아래 → 위 순서 |
| `.mat` 값을 바꿨는데 캐릭터가 그대로 | 플레이 중엔 복사본(`(Lab)`)을 씀 | **쉐이더** 탭 스타일 카드를 다시 누르기 (또는 플레이 다시 시작) |
| 순도를 바꿔도 차이가 거의 없음 | 디버그 보기가 **빛만**(바탕색 회색) / 바탕색이 흰색 / 스타일이 **리얼**(림 꺼짐) | **보통 화면**, 색 있는 바탕, 세미리얼·스타일라이즈드 |
| 쉐이더 탭 스위치로 공이 안 바뀜 | 스위치·스타일은 `LabCharacter` 캐릭터에만 | 공은 `MyLightBall` 인스펙터 체크박스로 |
| 노멀 맵 스위치를 꺼도 공이 그대로 | 공 머티리얼엔 노멀 맵이 없음 (+ 스위치는 캐릭터에만) | 노멀 맵은 캐릭터 얼굴·옷으로 확인 |
| 리얼 스타일에서 필·림 스위치를 켜도 안 생김 | 리얼 프리셋이 필·림을 끔. 스위치는 "끄기만" | B를 세미리얼·스타일라이즈드로 |
| 역광에서 얼굴 앞면이 아주 어두움 | 정상. 키 라이트가 뒤에 있음 | 이때 앞면을 밝히는 것이 환경광·필 라이트 → 필 스위치로 비교 |
| 조명 카드를 눌렀는데 필·림 위치가 그대로 | 정상. 조명 탭은 `Sun`만 바꿈 | 필·림은 머티리얼의 `Fill/Rim Direction (Camera Space)` |
