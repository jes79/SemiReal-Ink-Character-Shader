## 학습 목표

1. `Material Type`(Standard·Skin·Cloth)이 **쉐이더 키워드**라서 머티리얼마다 다른 코드가 돈다는 것을 설명할 수 있다.
2. 피부 SSS 근사·천 sheen·금속 BRDF·보석 표현이 쉐이더의 어느 줄에서 만들어지는지 찾고, 슬라이더로 바꿔 볼 수 있다.
3. 마스크 맵과 자동 판별(색으로 찾기)의 차이를 재질 판별 보기로 비교하고, 부위에 맞는 방법을 고를 수 있다.

## 개념 설명

### 1. 용어

| 용어 | 한 줄 풀이 | 이 프로젝트에서 |
|---|---|---|
| 재질 타입 (Material Type) | 머티리얼이 "피부냐, 천이냐, 보통이냐"를 고르는 칸 | `_MaterialType` (Standard / Skin / Cloth) |
| 키워드 (Keyword) | 쉐이더 코드 일부를 넣고 빼는 **컴파일 스위치** | `_MATERIALTYPE_SKIN`, `_MASKMAP` |
| 배리언트 (Variant) | 키워드 조합마다 따로 만들어진 쉐이더 한 벌 | 키워드가 늘면 배리언트도 는다 |
| SSS (Subsurface Scattering) | 빛이 피부 속으로 들어가 퍼졌다가 나오는 현상 | 이 쉐이더는 **근사**(비슷하게 흉내) |
| sheen (시인) | 천 표면 솜털이 비스듬한 빛을 받아 가장자리가 뿌옇게 빛나는 것 | Cloth 타입만 |
| BRDF | 빛이 표면에서 어느 방향으로 얼마나 튕기는지 정하는 계산식 | URP의 `InitializeBRDFData` + `DirectBRDFSpecular` |
| F0 | 정면에서 볼 때의 반사율. 보통 물체 약 4%, 금속은 자기 색 | 금속은 베이스 색이 곧 반사색 |
| 프레넬 (Fresnel) | 비스듬히 볼수록 반사가 세지는 현상 | 551행 `fresnel` |
| 마스크 맵 (Mask Map) | 색 대신 "여기는 금속" 같은 **정보**를 R·G·B에 담은 텍스처 | `Textures/FinalPlayer/Masks/*_Mask.png` |
| HSV | 색을 색상(H)·채도(S)·밝기(V) 세 숫자로 나타내는 방법 | 자동 판별 슬라이더가 이 세 값 기준 |

### 2. Material Type은 키워드다

`Shaders/SemiRealInk.shader` 56–57행 (찾을 글자: `KeywordEnum(`):

```hlsl
[Header(Material Type)]
[KeywordEnum(Standard, Skin, Cloth)] _MaterialType ("Material Type", Float) = 0
```

`KeywordEnum`은 고른 항목에 따라 키워드 하나를 켭니다. 이름 규칙은 **`_속성이름(대문자)_항목(대문자)`** 입니다.

| 인스펙터에서 고름 | 켜지는 키워드 | `_MaterialType` 값 |
|---|---|---|
| Standard | `_MATERIALTYPE_STANDARD` | 0 |
| Skin | `_MATERIALTYPE_SKIN` | 1 |
| Cloth | `_MATERIALTYPE_CLOTH` | 2 |

본체 패스(`ForwardLit`)는 276행에서 이 키워드들을 받습니다 (찾을 글자: `shader_feature_local _MATERIALTYPE`):

```hlsl
#pragma shader_feature_local _MATERIALTYPE_STANDARD _MATERIALTYPE_SKIN _MATERIALTYPE_CLOTH
#pragma shader_feature_local_fragment _MASKMAP
```

> **shader_feature**: 머티리얼이 실제로 쓰는 키워드 조합만 빌드에 넣는다. **local**: 이 쉐이더 안에서만 쓰는 키워드.

코드에서는 `#if defined(...)`로 피부·천 코드를 **통째로 넣고 뺍니다**. Standard 머티리얼에는 피부 코드가 아예 없습니다.

| 키워드 | 쓰이는 곳 (줄) | 하는 일 |
|---|---|---|
| `_MATERIALTYPE_SKIN` | 389, 479, 524, 591 | SSS 명암·투과광, 판별 보기 붉은 기, 노멀 흐리게, 림 붉게 |
| `_MATERIALTYPE_CLOTH` | 481, 515, 597 | 판별 보기 푸른 기, 하이라이트 줄이기, sheen |
| `_MASKMAP` | 352 | 마스크 맵으로 판별 (없으면 색으로 자동 판별) |

**기능 스위치(Features)와 무엇이 다른가** — 자세한 비교는 4차시에서 합니다.

| | Material Type (키워드) | 기능 스위치 `Skin Subsurface` 등 (`[ToggleUI]` 값) |
|---|---|---|
| 정하는 것 | 이 머티리얼이 **무슨 재질인가** | 이미 있는 기능을 **잠깐 끌까** |
| 바뀌는 때 | 머티리얼을 만들 때 한 번 | 랩에서 수시로 (끄고 켜기) |
| 비용 | 안 쓰는 코드가 빠져서 가볍다 | 코드는 그대로, 값만 0/1 |
| 관계 | `피부 SSS` 스위치는 **Skin 타입일 때만** 효과가 있다 (390행 `if (_EnableSubsurface > 0.5h)`가 `#if defined(_MATERIALTYPE_SKIN)` 안에 있음) | |

**스크립트로 바꿀 때 주의**: 인스펙터에서 고르면 Unity가 키워드를 같이 바꿔 주지만, 스크립트에서 `SetFloat("_MaterialType", 1)`만 하면 **키워드는 그대로**입니다. 장면 메뉴는 그래서 키워드를 직접 켭니다.

```csharp
// Editor/SemiRealInkTestSetup.cs 283–290행 (찾을 글자: "static void SetSurfaceType")
static void SetSurfaceType(Material m, SurfaceType type)
{
    m.SetFloat("_MaterialType", (float)type);
    m.DisableKeyword("_MATERIALTYPE_STANDARD");
    m.DisableKeyword("_MATERIALTYPE_SKIN");
    m.DisableKeyword("_MATERIALTYPE_CLOTH");
    m.EnableKeyword("_MATERIALTYPE_" + type.ToString().ToUpperInvariant());
}
```

FinalPlayer 머티리얼은 장면 메뉴의 `ApplyPreset`(같은 파일 202–281행)이 이름을 보고 재질을 정했습니다.

| 머티리얼 (`Materials/FinalPlayer_SemiRealInk/`) | Material Type | 마스크 맵 | 코드 근거 |
|---|---|---|---|
| `Head_Quad_Skin.003`, `Body_Quad_Skin.001`, `Body_Rebuilt_ThighSkin` | Skin | 없음 (Detect 3개 모두 0) | 218행 `Contains("Skin")` |
| `Jeogori_SingleLayer_BlueOutside_RedInside`, `VARCO_OutterChima_BlueOutside_RedInside.001` | Cloth | 있음 (Metal Detect 0.7) | 242행 `Jeogori`·`Chima` |
| `material_0.007` (머리카락) | Cloth | 있음 | 257행 |
| `material_0.004` (칼), `material_0.018` (고글), `Boots_Quad_Surface.001`, 나머지 `material_0.0xx` | Standard | 있음 | 205행 기본값 |

### 4. 피부: SSS 근사

진짜 SSS는 빛이 피부 속을 돌아다니는 길을 계산해야 해서 무겁습니다. 이 쉐이더는 **네 가지 요령**으로 비슷하게 보이게 합니다(README 알려진 한계: "두께 맵 없이 투과광을 계산").

| 요령 | 줄 | 인스펙터 칸 (Skin Subsurface Scattering) | 눈에 보이는 것 |
|---|---|---|---|
| ① 색마다 다른 랩 라이팅 | 393–395 | Scatter Width | 명암 경계가 붉고 부드럽다 |
| ② 붉은 반그림자 | 397–400 | Subsurface Color | 드리운 그림자(코·모자 챙 그림자 등)의 가장자리가 붉게 번진다 |
| ③ 투과광 | 402–404 | Transmission (Back Light), Transmission Focus, Transmission Distortion | 역광에서 피부가 붉게 비친다 |
| ④ 확산광 노멀 흐리게 | 524–525 | Diffuse Normal Blur | 모공·잔주름이 거칠게 안 보인다 |
| (덤) 림 붉게 | 591–592 | Subsurface Color | 피부 테두리가 살짝 붉다 |

> **랩 라이팅(Wrap Lighting)**: 빛이 닿는 범위를 그늘 쪽으로 조금 "감싸" 넘기는 요령. 명암 경계가 부드러워진다.

393–395행 (찾을 글자: `half3 w = _ScatterWidth`):

```hlsl
half3 w = _ScatterWidth * half3(1.0h, 0.45h, 0.25h);
half3 wrapped = saturate((NdotL + w) / (1.0h + w));
half3 shade = lerp(ShadeTerm(NdotL).xxx, wrapped, max(_Realism, 0.6h));
```

빨강(R)은 1.0, 초록(G)은 0.45, 파랑(B)은 0.25 만큼만 감쌉니다. **빨강이 그늘 쪽으로 가장 멀리 넘어갑니다.**
숫자로 보면 (`Scatter Width` = 0.55, 그늘 쪽 `NdotL` = -0.2):

| 채널 | w | (NdotL + w) / (1 + w) | 결과 |
|---|---|---|---|
| R | 0.55 | 0.35 / 1.55 | **0.23** |
| G | 0.25 | 0.05 / 1.25 | 0.04 |
| B | 0.14 | 음수 → 0 | 0 |

→ 그늘인데도 빨강만 0.23 남아서 **붉은 경계**가 됩니다. `NdotL`은 2차시의 N·L(표면 방향과 빛 방향이 얼마나 맞는지)입니다.

> **헷갈리기 쉬운 점**: 명암 경계의 붉은 기(①)는 고정 비율 `(1.0, 0.45, 0.25)`에서 나오고, 넓이만 `Scatter Width`로 정합니다. `Subsurface Color`는 ② 반그림자·③ 투과광·림 색에 쓰입니다.

`max(_Realism, 0.6h)`: Realism을 0(스타일라이즈드)으로 내려도 피부는 **최소 60%는 부드러운 명암**을 씁니다. 그래서 스타일라이즈드에서도 얼굴이 딱딱하게 끊기지 않습니다.

투과광(402–404행, 찾을 글자: `half3 transDir`):

```hlsl
half3 transDir = light.direction + N * _TransmissionDistortion;
half trans = pow(saturate(dot(V, -transDir)), _TransmissionPower) * _TransmissionStrength;
transmission = trans * _SubsurfaceColor.rgb * lerp(1.0h, shadow, 0.5h) * light.distanceAttenuation;
```

| 값 | 뜻 |
|---|---|
| `dot(V, -transDir)` | 카메라가 **빛을 마주 볼수록**(빛이 캐릭터 뒤에 있을수록) 커진다 |
| `_TransmissionPower` (Transmission Focus) | 클수록 빛 쪽을 정확히 볼 때만 좁게 생긴다 |
| `_TransmissionDistortion` | 표면 방향(N)으로 빛 방향을 휘게 해서, 굽은 곳마다 다르게 생긴다 |

[그림: 그래프 — 가로축 N·L(-1~1), 세로축 밝기. 회색 선(람버트)은 0에서 끊기고, 빨강 선은 -0.55까지, 초록·파랑 선은 그보다 짧게 이어지는 모습]

### 5. 천: sheen

596–600행 (찾을 글자: `half sheen = pow`):

```hlsl
#if defined(_MATERIALTYPE_CLOTH)
    half sheen = pow(1.0h - NdotV, _SheenPower) * _SheenIntensity * (1.0h - metallic) * _EnableSheen;
    color += _SheenColor.rgb * sheen * (mainLight.color * keyShade + ambient);
#endif
```

| 부분 | 뜻 |
|---|---|
| `1.0h - NdotV` | 정면(카메라를 보는 면) = 0, 가장자리(비스듬한 면) = 1에 가깝다 |
| `pow(…, _SheenPower)` (Sheen Falloff) | 클수록 **가장자리에만** 좁게. 예: 가장자리 0.8일 때 Falloff 4 → 0.41, Falloff 8 → 0.17 |
| `(1.0h - metallic)` | 금속으로 판별된 곳(금실 자수)에는 sheen이 **없다** |
| `mainLight.color * keyShade + ambient` | 빛을 받는 쪽일수록 밝다. 그늘에서는 환경광만큼만 |

천은 하이라이트도 줄입니다 (515–517행, 찾을 글자: `surfaceSpec = lerp(_ClothSpecular`):

```hlsl
surfaceSpec = lerp(_ClothSpecular, 1.0h, saturate(metallic + gem));
```

→ 천 부분은 `Cloth Specular Scale`(기본 0.3)배로 줄이고, **금속·보석으로 판별된 곳은 1배 그대로**. 그래서 같은 치마 안에서 천은 무광, 금실은 반짝입니다.
머리카락(`material_0.007`)도 Cloth 타입입니다. 대신 `Cloth Specular Scale` 0.8, `Sheen Intensity` 0.25로 윤기를 더 남겼습니다 (`SemiRealInkTestSetup.cs` 257–264행).

### 6. 금속: URP BRDF + 환경 반사

502행 `InitializeBRDFData(albedo, metallic, …)`는 URP가 주는 함수입니다. metallic 값 하나로 확산과 반사를 나눕니다.

| | 보통 물체 (metallic 0) | 금속 (metallic 1) |
|---|---|---|
| 확산색 (`brdf.diffuse`) | 베이스 색 | **0 (검정)** |
| 반사색 F0 (`brdf.specular`) | 약 4% 회색 | **베이스 색** (금은 금빛 반사) |
| 무엇으로 보이나 | 자기 색 + 흰 하이라이트 | 주변이 비친 모습(환경 반사) + 색 있는 하이라이트 |

그래서 금속은 **비칠 것(반사 프로브·하늘)이 없으면 검게** 보입니다. 시연 D-14에서 **환경 반사**를 끄자 어두워진 이유입니다 (548–551행, 찾을 글자: `GlossyEnvironmentReflection`).

이 쉐이더가 금속에 더한 손질:

| 칸 (Auto Detect Gold Brass Copper) | 줄 | 하는 일 |
|---|---|---|
| Metal Smoothness | 497 | 금속 자리는 이 매끈함을 쓴다 (기본 0.78) |
| Metal Color Saturation | 506–509 | 반사색 채도를 올린다. 베이지 금실이 차가운 하늘을 비춰 **은색처럼 보이는 것**을 막는다 |
| Metal Shine Boost | 519, 551 | 금속 자리만 하이라이트·환경 반사를 더 키운다 |
| — | 581–582 | 필 라이트에서도 두 번째 하이라이트가 생긴다 |

치마·저고리는 `Metal Detect` 0.7, `Metal Shine Boost` 1.8, `Metal Color Saturation` 1.5로 맞췄습니다 (`SemiRealInkTestSetup.cs` 244–251행). 금실을 "70%만 금속"으로 둬서 반사가 없는 각도에서도 검게 죽지 않게 한 것입니다.

> **하이라이트 모양**: 384행 주석대로 키 라이트 하이라이트는 GGX(URP `DirectBRDFSpecular`)로 계산합니다. 매끈할수록 작고 또렷합니다.

### 8. 마스크 맵 vs 자동 판별

판별은 `ComputeMasks` 함수 하나가 합니다 (349–373행, 찾을 글자: `SurfaceMasks ComputeMasks`).

```hlsl
#if defined(_MASKMAP)
    half4 mask = SAMPLE_TEXTURE2D(_MaskMap, sampler_MaskMap, uv);
    m.metal = mask.r * _MetalDetect;
    m.silver = mask.b * _SilverDetect;
    m.gem = mask.g * _GemDetect;
#else
    half3 hsv = RgbToHsv(LinearToSRGB(baseLinear));
    m.metal = HueMask(hsv.x, _MetalHue, _MetalHueWidth)
            * smoothstep(_MetalSatMin, _MetalSatMin + 0.1h, hsv.y)
            * smoothstep(_MetalValMin, _MetalValMin + 0.12h, hsv.z)
            * _MetalDetect;
    …
#endif
```

| | 마스크 맵 (`Use Mask Map` 켬) | 자동 판별 (끔) |
|---|---|---|
| 판단 근거 | 사람이 칠한 R·G·B 정보 | 베이스 텍스처 색의 색상·채도·밝기 |
| 채널 | **R = 금속**, **G = 유리·보석**, **B = 은·거울** | — |
| Detect 슬라이더 | 각 채널의 **세기** (0.7이면 70%만 금속) | 판별 결과의 세기 |
| 장점 | 정확하다. 같은 색이어도 부위를 나눌 수 있다 | 텍스처 한 장 없이 바로 된다 |
| 약점 | 마스크 텍스처를 따로 만들어야 한다 | **같은 색이면 구별 못 한다** (노란 천 무늬 = 금, 흰 무늬 = 은으로 잡힐 수 있다) |
| 이 프로젝트 | 피부를 뺀 모든 FinalPlayer 머티리얼 | 마스크가 없을 때. 피부는 Detect를 모두 0으로 꺼 둠 |

자동 판별 슬라이더 읽는 법:

| 머리글 | 칸 | 뜻 |
|---|---|---|
| Auto Detect Gold Brass Copper | Hue Center / Hue Width | 어떤 색상을 금으로 볼까 (0.115 ≈ 주황빛 노랑) / 얼마나 넓게 |
| | Saturation Min / Brightness Min | 이보다 진하고, 이보다 밝아야 금 |
| Auto Detect Silver Steel Mirror | Saturation Max / Brightness Min | 이보다 **흐리고**(무채색), 이보다 밝으면 은 |
| Auto Detect Glass Gem | Hue Center / Hue Width / Saturation Min | 어떤 색상을 보석으로 볼까 (0.42 ≈ 초록) |

> **색상환**: 색상(H)은 0~1로 한 바퀴. 0과 1은 둘 다 빨강이라 이어져 있다 → `HueMask` 345행 `min(d, 1.0h - d)`.

- 자동 판별은 **사람이 보는 색(sRGB)** 으로 바꿔서 판단합니다(358–359행). 그래야 슬라이더 숫자가 눈으로 본 색과 맞습니다.
- **베이스 맵을 꺼도** 판별은 텍스처 원래 색으로 합니다(428–429행). 끄면 흰색이라 전부 은으로 잡히기 때문입니다.
- 메탈릭 맵과 판별 결과는 **더해집니다**(462–463행). 둘 중 하나라도 금속이면 금속.

**마스크는 데이터 텍스처**: `Editor/MaskTextureImporter.cs`가 이름이 `_Mask.png`로 끝나는 텍스처의 sRGB를 끕니다 (14행 `importer.sRGBTexture = false;`).

```csharp
// 3–4행 주석
// 이름이 "_Mask.png"로 끝나는 텍스처는 색이 아니라 데이터(마스크)이므로 sRGB 변환을 끈다.
// (sRGB가 켜져 있으면 0.5 같은 중간값이 어둡게 바뀌어 재질 판별 경계가 틀어진다)
```

> **sRGB**: 사람 눈에 맞춰 어두운 쪽을 촘촘하게 저장하는 색 방식. 색 그림에는 맞지만, "0.5 = 반만 금속" 같은 숫자 정보에는 틀린 값이 된다.

마스크 연결은 장면 메뉴가 합니다: 베이스 텍스처 이름 + `_Mask.png`를 `Textures/FinalPlayer/Masks/`에서 찾아 넣고 `_MASKMAP` 키워드를 켭니다 (`SemiRealInkTestSetup.cs` 172–186행, 찾을 글자: `static void AssignMaskMap`).

[그림: 마스크 맵 한 장을 R·G·B 채널로 쪼갠 세 장 — R(금장 자리만 흰색), G(렌즈만 흰색), B(은 테만 흰색). 옆에 재질 판별 보기의 노랑·초록·흰색과 화살표로 연결]

## 정리

- 재질 = **Material Type 키워드**(코드를 넣고 뺌) + **판별 결과**(금속·은·보석, 픽셀마다) + 슬라이더 값.
- 피부 SSS는 4가지 근사: 색마다 다른 랩 라이팅 · 붉은 반그림자 · 투과광 · 확산광 노멀 흐리게.
- 천 sheen = `pow(1 - N·V, Falloff)` → 가장자리 광택. 금속으로 판별된 곳(금실)은 빠진다.
- 금속 = 확산 0 + 베이스 색 반사. **환경 반사가 없으면 검다.** Metal Smoothness · Shine Boost · Color Saturation으로 손질.
- 보석 = 매끈 + 반사율 높게 + 속 색 줄임 + 정면 속빛. 불투명이다.
- 마스크 맵(R 금속·G 보석·B 은, sRGB 끔)은 정확하고, 자동 판별(HSV)은 바로 되지만 같은 색을 구별 못 한다.
- 플레이 중 `.mat`을 고치면 **스타일 카드를 눌러야** 복사본에 반영되고, **멈춰도 남는다**.

보고서에 넣을 것 (한 파일, PDF 또는 Markdown):

1. 목표 한 줄 (예: "역광에서 귀·얼굴 가장자리 혈색을 더 살린다")
2. 캡처 4장 — **같은 시점·같은 환경·같은 조명**(권장: **중립 스튜디오** + **측면광** 또는 **역광**), **B만 (4)**
   - 바꾸기 전 / 바꾼 뒤 / 바꾼 뒤 `M`(재질 판별 보기) / 다른 조명 하나에서 바꾼 뒤
3. 바꾼 값 표

|---|---|---|---|---|
| 예: Scatter Width | `_ScatterWidth` | 0.55 | 0.7 | 측면광에서 붉은 경계를 넓히려고 |

4. 코드 연결 3줄 — 바꾼 칸이 쉐이더 몇 행에서 어떻게 쓰이는지 (예: "`_ScatterWidth`는 393행에서 R·G·B 감싸기 폭이 된다")

|---|---|---|
| 캡처 4장 | 같은 시점·환경·조명, 이름표(`B  …`)가 보인다 | 25 |

## 확인 질문

1. 스크립트에서 `m.SetFloat("_MaterialType", 1f)`만 했더니 피부 SSS가 생기지 않았다. 왜일까?
   - **정답**: SSS 코드는 `#if defined(_MATERIALTYPE_SKIN)` 안에 있다. 값만 바꾸면 키워드는 그대로이므로 `SetSurfaceType`처럼 `EnableKeyword("_MATERIALTYPE_SKIN")`(다른 두 키워드는 `DisableKeyword`)도 해야 한다.
2. 마스크 텍스처(`*_Mask.png`)는 왜 sRGB를 끄는가?
   - **정답**: 색이 아니라 데이터(0.5 = 반만 금속)이기 때문. sRGB가 켜져 있으면 0.5 같은 중간값이 어둡게 바뀌어 판별 경계가 틀어진다 (`MaskTextureImporter.cs`).
3. 스타일라이즈드(Realism 0)로 바꿨는데도 얼굴 명암 경계는 다른 부위보다 부드럽다. 어느 줄 때문인가?
   - **정답**: 395행 `max(_Realism, 0.6h)`. 피부는 Realism이 0이어도 랩 라이팅 명암을 최소 60% 섞는다.

|---|---|---|
| `.mat` 값을 바꿨는데 화면이 그대로 | 플레이 중 캐릭터는 복사본(`(Lab)`)을 쓴다 | **쉐이더** 탭 스타일 카드(예: **세미리얼**)를 한 번 누른다 |

| **피부 SSS** / **천 광택 (Sheen)** 스위치를 켜도 변화 없음 | Material Type이 Skin / Cloth가 아니다. 또는 스위치는 "끄기만" 한다 | 인스펙터 Material Type 확인 → 카드 누르기 |
| 금실 자수에 sheen이 안 생긴다 | 일부러 뺐다: `(1.0h - metallic)` (598행) | 정상 |
| **러프니스 (흰색 = 거침)** 보기에서 금속·보석이 매끈하게 안 보인다 | 이 보기(471행)는 `Smoothness (No Map)`/러프니스 맵 값만 보여 준다. `Metal Smoothness`·`Gem Smoothness`는 그 뒤 497–498행에서 섞인다 | 정상. 금속 매끈함은 **반사광만** 보기로 확인 |
| 금속이 검게 보인다 | **환경 반사** 스위치가 꺼져 있거나 **Surface** 머리글의 `Environment Reflection` 슬라이더가 0 | **쉐이더** 탭 **환경 반사** 켜기, 슬라이더 값 확인 (기본 1) |
| `Use Mask Map` 을 끄니 흰 무늬가 은(흰색)으로 잡힌다 | 자동 판별은 "흐리고 밝은 색 = 은"이라 흰 무늬와 은을 구별 못 한다 | `Silver Detect` 낮추기, `Saturation Max`·`Brightness Min` 조절, 또는 마스크 맵 쓰기 |
| 투과광이 안 보인다 | 빛이 앞에 있다 / 세기가 작다 (기본 0.35) | **조명** 탭 **역광**, 카메라는 캐릭터 정면, **Transmission (Back Light)** 를 올린다 |
| 실습 6 뒤 캐릭터가 분홍색 | 쉐이더 컴파일 오류 | Console 오류 줄 확인. `undeclared identifier '_TransmissionColor'` 면 ② CBUFFER 줄 빠짐 |
| 쉐이더 인스펙터에 SRP Batcher "not compatible" | 새 값을 `CBUFFER_START(UnityPerMaterial)` 밖에 선언했다 | ② 줄을 `CBUFFER_START` ~ `CBUFFER_END` 사이로 옮긴다 |
| 실습 6 뒤 줄 번호가 교안과 다르다 | 위에서부터 고치면 아래 줄이 밀린다 | **찾을 글자(Ctrl+F)** 로 찾는다. 다음엔 아래쪽부터 고친다 |
