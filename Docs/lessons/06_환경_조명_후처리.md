# 6차시. 환경·조명·후처리

| 항목 | 내용 |
|---|---|
| 수업 시간 | 180분 (시연 25 · 개념 45 · 쉬는 시간 10 · 실습 70 · 정리·과제 20 · 도입 10) |
| 난이도 | ★★☆ (에셋 만들기 + C# 몇 줄 고치기) |
| 시작 저장 지점 | `shader-lab-v2` |
| 쓰는 랩 탭 | **환경 · 조명 · 후처리** (맵·보기의 디버그 보기 조금) |

> 기준 버전: Unity 6000.6.7f1 · URP 17.6 (SRP Core 17.6.0). 줄 번호는 `shader-lab-v2` 기준입니다.

## 학습 목표

1. 환경 프리셋 하나가 하늘·햇빛·환경광·안개·반사·후처리·배경 소품을 한 번에 바꾸는 과정을 코드(`SetEnvironment`)에서 따라 읽을 수 있다.
2. 반사 프로브(큐브맵)와 Volume 프로필(톤매핑·노출·블룸 …)이 캐릭터 화면에 무엇을 더하는지 랩에서 보여 줄 수 있다.
3. 새 `EnvironmentPreset` 에셋과 새 조명 프리셋을 만들어 랩 목록에 넣고, 환경을 바꿀 때 생기는 버그를 찾아 고칠 수 있다.

## 시작 저장 지점

5차시와 같은 `shader-lab-v2`입니다. 새 연습 브랜치를 만듭니다. **Unity를 닫고** 실행합니다.

```bash
git status                              # 바뀐 파일이 있으면 먼저 commit 하거나 git stash
git switch -c lesson06 shader-lab-v2
git lfs pull
```

- 확인: `git branch` 에 `* lesson06`
- 장면: `Assets/CharacterShaderTest/Scenes/CharacterShaderTest.unity` → ▶ 플레이. 캐릭터는 **갑옷 (VARCO)** 을 입고 나온다.

## 시연 순서

### A. 환경 탭 — 다섯 가지 세상 (10분)

1. ▶ 플레이. **비교** 탭에서 **A (왼쪽)** = `원본 (URP Lit)`, **B (오른쪽)** = `세미리얼` (처음 값 그대로). 비교 방식 **와이프 (1)**.
2. **환경** 탭. "환경 프리셋" 아래 카드 5장을 위에서부터 누른다: **얼어붙은 세상 → 중립 스튜디오 → 맑은 한낮 → 노을 → 달밤**.
3. 카드마다 다섯 곳을 손으로 가리킨다.

| 볼 곳 | 무엇이 바뀌나 |
|---|---|
| 배경 | 하늘 (스카이박스) |
| 그림자 방향·진하기 | 햇빛 (장면의 `Sun` 라이트) |
| 그늘진 쪽 색 | 환경광 (하늘·지평선·바닥 3색) |
| 먼 바닥·지평선 | 안개 |
| 갑옷 금속에 비친 것 | 반사 (구워 둔 큐브맵) |

4. **맵·보기** 탭 → 디버그 보기 **반사광만**. 다시 **환경** 탭에서 카드를 바꾼다. 갑옷에 비친 색이 환경마다 다르다.
5. 디버그 보기 **빛만 (회색 점토)**. 환경을 바꾸면 회색 캐릭터의 그늘 색이 바뀐다 (= 환경광). 끝나면 **보통 화면**.
6. 플레이 중 Hierarchy에서 `Env_FrozenWorld`, `Env_Studio`, `Env_Outdoor`를 보여 준다. "환경마다 바닥 소품 묶음 하나를 켠다."

> **강사 메모:** 코드대로라면 맑은 한낮·노을에서는 바닥 소품(`Env_Outdoor`)이 켜지지 않습니다. 그것이 오늘 과제의 **소품 버그**입니다. 시연에서는 짚지 말고 넘어갑니다 (실습 5에서 학생이 직접 찾게 함).

![환경 프리셋 (노을)](../images/lab_environment_sunset.png)

### B. 조명 탭 — 같은 환경, 다른 빛 (6분)

7. **환경** = **맑은 한낮**. **조명** 탭 → "조명 프리셋" 카드: **환경 기본 → 45° 키 라이트 → 역광 → 탑라이트**. (2차시에 본 내용. 빠르게)
8. "햇빛 돌리기"의 **방향 (도)** 슬라이더를 끌어 그림자가 캐릭터 둘레를 도는 것을 보여 준다. 끝나면 `0`.
9. **환경** = **달밤**, **조명** = **3점 조명 + 포인트**. 따뜻한 포인트 라이트(횃불)와 차가운 역광 포인트가 켜진다. Hierarchy의 `Accent Lights` 아래 `Warm Key (Torch)`, `Cool Rim`이 켜진 것을 보여 준다.

[그림: 달밤 + "3점 조명 + 포인트". 왼쪽 앞 따뜻한 빛, 오른쪽 뒤 푸른 테두리에 화살표]

### C. 후처리 탭 — 화면 마무리 (9분)

10. **환경** = **얼어붙은 세상**, **조명** = **환경 기본**. **후처리** 탭.
11. "후처리 전체"의 **후처리 켜기 (P)** 를 껐다 켠다 (`P` 키도 같음). 꺼지면 푸른 색보정·비네트·필름 그레인이 모두 빠진다.
12. "톤매핑 · 노출"의 **톤매핑** 드롭다운: `None` → `Neutral` → `ACES`. 갑옷 하이라이트와 하늘의 밝은 곳을 비교한다.
13. **노출 (EV)** 슬라이더를 `-1`, `+1`로 움직인다. 화면 전체가 반, 두 배로 어두워지고 밝아진다.
14. "효과 하나씩 끄기"에서 **블룸 (빛 번짐)**, **비네트 (가장자리 어둡게)**, **필름 그레인 (입자)** 를 하나씩 끈다.
15. **문제 내기:** **환경** = **중립 스튜디오**로 바꾸고 다시 **후처리** 탭을 본다. 스튜디오 프로필에는 효과가 **2개(톤매핑·색 조정)** 뿐인데, 목록에는 얼어붙은 세상의 **7개**가 그대로 있다. 화면도 여전히 푸르다.
    - "환경을 바꿨는데 후처리는 안 바뀌었다. 왜일까?" → 개념 설명 6과 실습 2에서 푼다.

[그림: 후처리 탭. 얼어붙은 세상 = 효과 7개 / 중립 스튜디오로 바꾼 뒤에도 7개 (버그) / 고친 뒤 2개]

### 3. `SetEnvironment` 따라 읽기 (8분)

`Scripts/ShaderLabController.cs` 135–178행 (찾을 글자: `public void SetEnvironment`). 환경 카드를 누르면 이 함수가 불립니다.

| 줄 | 하는 일 | 화면에서 |
|---|---|---|
| 142 | `RenderSettings.skybox = env.skybox` | 배경 하늘 |
| 143–146 | 환경광을 **Trilight(3색)** 로 정하고 하늘·지평선·바닥 색 넣기 | 그늘 색 |
| 147–150 | 안개 켜기/끄기, 방식 `ExponentialSquared`, 색, 밀도 | 먼 곳이 뿌옇게 |
| 151 | `DynamicGI.UpdateEnvironment()` — 바뀐 환경광을 다시 계산 | |
| 153–157 | 반사 프로브를 Custom으로, 큐브맵 = `env.reflection` | 금속에 비친 것 |
| 159–166 | 모든 환경의 소품 묶음을 돌며 켜고 끄기 | 바닥·눈발 |
| 168–174 | Volume에 후처리 프로필 넣기 | 색감·블룸·비네트 |
| 176 | `ApplyLighting()` — 햇빛 색·세기·방향 | 그림자 |
| 177 | `NotifyChanged()` — UI 다시 그리기 | 카드 선택 표시 |

```csharp
// ShaderLabController.cs 143–150행
RenderSettings.ambientMode = AmbientMode.Trilight;
RenderSettings.ambientSkyColor = env.ambientSky;
...
RenderSettings.fogMode = FogMode.ExponentialSquared;
RenderSettings.fogDensity = env.fogDensity;
```

- 환경광은 **3색으로만** 정합니다 (143행). 하늘 그림(스카이박스)은 환경광 계산에 쓰지 않습니다.
- **Exponential Squared 안개**: 안개 양 = `1 − exp(−(밀도 × 거리)²)`. 캐릭터는 카메라와 가까워서 밀도 0.03 정도로는 거의 안 흐려집니다. 먼 바닥·지평선이 먼저 묻힙니다.

**쉐이더는 이 값을 어디서 받나** (`Shaders/SemiRealInk.shader`, `Name "ForwardLit"` 패스)

| 받는 것 | 줄 | 찾을 글자 | 끄는 스위치 (쉐이더 탭) |
|---|---|---|---|
| 환경광 (SH) | 546 | `SampleSH(Nd)` | (없음) |
| 그늘 색 | 548–549 | `shadowTint` | 그늘 색 |
| 환경 반사 (반사 프로브) | 550–553 | `GlossyEnvironmentReflection` | 환경 반사 |
| 안개 준비 | 289, 330 | `multi_compile_fog`, `ComputeFogFactor` | (없음) |
| 안개 섞기 | 611 | `MixFog(color` | (없음) |

```hlsl
// SemiRealInk.shader 546행, 551–553행
half3 ambient = SampleSH(Nd) * _AmbientStrength * aoIndirect;
...
half3 envRefl = GlossyEnvironmentReflection(reflectDir, input.positionWS, brdf.perceptualRoughness, aoIndirect, screenUV);
half fresnel = Pow4(1.0h - NdotV);
color += envRefl * EnvironmentBRDFSpecular(brdf, fresnel) * _ReflectionStrength * surfaceSpec * metalBoost * _EnableEnvReflection;
```

- `brdf.perceptualRoughness`: 거친 면일수록 **흐린 큐브맵**을 읽는다. 그래서 거울은 또렷하게, 거친 금속은 뿌옇게 비친다.
- 먹 아웃라인 패스도 727행 `MixFog(ink, …)`로 안개를 받는다. 그래서 안개 속에서도 선만 튀지 않는다.

### 4. 반사 프로브 — 구워 둔 큐브맵 (7분)

[그림: 캐릭터 가슴 높이에 공 모양 프로브. 위·아래·앞·뒤·좌·우 6장 사진이 펼쳐진 큐브맵. 캐릭터는 찍히지 않음]

| 단계 | 어디 | 줄 |
|---|---|---|
| 프로브 만들기: Custom 모드, 크기 40×20×40, **캐릭터 레이어는 안 찍음** (`cullingMask = ~characterMask`) | `SemiRealInkTestSetup.cs` `BuildScene` | 714–721 |
| 환경마다 미리 적용(`PreviewEnvironment`) → 굽기 → `*_Reflection.exr` 저장 → 프리셋의 Reflection 칸에 넣기 | 같은 파일 `BakeEnvironmentReflections` | 1050–1066 |
| 플레이 중 환경을 바꾸면 프로브의 큐브맵만 바꿔 끼움 | `ShaderLabController.cs` | 153–157 |

```csharp
// ShaderLabController.cs 153–157행
if (reflectionProbe != null && env.reflection != null)
{
    reflectionProbe.mode = ReflectionProbeMode.Custom;
    reflectionProbe.customBakedTexture = env.reflection;
}
```

- **굽는다(Bake)**: 실행 중에 매 프레임 찍지 않고, 미리 한 번 찍어 파일로 저장해 두는 것. 싸고 빠르다.
- 캐릭터를 안 찍는 이유: 캐릭터가 자기 몸을 자기 갑옷에 비추면 이상해 보인다.
- **주의**: `env.reflection`이 비어 있으면(153행 조건) 프로브는 **그대로** 둔다. 즉 **직전 환경의 하늘**이 계속 비친다. 새 프리셋을 만들 때 Reflection 칸을 꼭 채운다.
- 장면 메뉴 **Build Test Scene**은 기본 환경 5개만 굽습니다(`CreateEnvironmentPresets`가 만든 목록). 새 환경은 기존 `.exr` 중 하나를 골라 씁니다.

### 5. 조명 프리셋 — 장면 안에 사는 값 (5분)

조명 프리셋은 환경 프리셋과 **저장 위치가 다릅니다**.

| | 환경 프리셋 | 조명 프리셋 |
|---|---|---|
| 코드 | `EnvironmentPreset.cs` (ScriptableObject) | `ShaderLabController.cs` 15–27행 `class LightingPreset` (`[Serializable]`) |
| 저장 위치 | Project 창의 `.asset` 파일 | **장면 안** `Shader Lab` 오브젝트의 **Lighting Presets** 목록 |
| 새로 만들기 | **Create → Shader Lab → Environment Preset** | 목록의 **+** 버튼 |
| Build Test Scene 후 | 파일은 남음 (목록에 다시 넣으면 됨) | **사라짐** (기본 7개로 다시 만들어짐) |

> **`[Serializable]`**: C# 클래스를 인스펙터에 칸으로 보이고 장면에 저장되게 하는 표시.

| 칸 | 뜻 |
|---|---|
| Display Name / Description | 조명 탭 카드 제목·설명 |
| Use Environment Sun | 켜면 환경 프리셋의 햇빛 방향을 그대로 씀 (Sun Angles 무시) |
| Sun Angles | 끈 경우의 햇빛 방향 (x 높이, y 방향) |
| Intensity Scale | 환경 햇빛 세기에 곱하는 배수 |
| Accent Lights | 보조 포인트 라이트(따뜻한 키·차가운 역광)를 켬 |

// ShaderLabController.cs 212–216행

### 6. Volume 프로필 — 원본과 복사본 (8분)

후처리 효과는 장면의 `Global Volume`(Volume 컴포넌트)이 겁니다. Volume에는 프로필 칸이 **두 개** 있습니다.

| 이름 | 뜻 | 고치면 |
|---|---|---|
| `volume.sharedProfile` | 원본 프로필 **파일** | `.asset` 파일이 바뀐다 |
| `volume.profile` | 처음 읽을 때 원본을 **복사해 만든 실행용 사본** | 파일은 안전 |

1차시의 **머티리얼 복사본 `(Lab)`** 과 같은 생각입니다. 랩은 플레이 중 후처리를 끄고 켜도 파일이 안 바뀌게 일부러 복사본을 씁니다.

```csharp
// ShaderLabController.cs 168–174행
if (volume != null)
{
    volume.sharedProfile = env.profile;
    // volume.profile을 읽으면 복사본이 생긴다 → 플레이 중 후처리를 끄고 켜도 프로필 파일은 그대로
    if (env.profile != null)
        _ = volume.profile;
}
```

**함정**: Unity의 `Volume.cs` (Packages → Scriptable Render Pipeline Core → `Runtime/Volume/Volume.cs`)를 열어 보면:

| 줄 (SRP Core 17.6.0) | 코드 | 뜻 |
|---|---|---|
| 81–95 | `if (m_InternalProfile == null) { … 복사 … }` | 복사본은 **없을 때 한 번만** 만든다 |
| 99 | `set => m_InternalProfile = value;` | `volume.profile = null` 로 복사본을 비울 수 있다 |
| 114 | `profileRef => m_InternalProfile == null ? sharedProfile : m_InternalProfile` | 복사본이 있으면 **원본 칸은 보지 않는다** |

→ 처음 환경(얼어붙은 세상)에서 복사본이 생긴 뒤에는 `sharedProfile`을 바꿔도 **화면도, 후처리 탭 목록도 얼어붙은 세상 그대로**입니다. 시연 15번에서 본 버그입니다. 실습 2에서 고칩니다.

| 프로필 | 톤매핑 | 들어 있는 효과 (후처리 탭 이름) |
|---|---|---|
| `FrozenWorld_Volume` | Neutral | 톤매핑, 화이트 밸런스 (색온도), 색 조정 (노출·대비·채도), 어두운 곳·중간·밝은 곳 색, 블룸 (빛 번짐), 비네트 (가장자리 어둡게), 필름 그레인 (입자) — 7개 |
| `Studio_Volume` | Neutral | 톤매핑, 색 조정 — 2개 |
| `Noon_Volume` | ACES | 톤매핑, 색 조정, 블룸, 비네트 — 4개 |
| `Sunset_Volume` | ACES | 톤매핑, 화이트 밸런스, 색 조정, 블룸, 비네트 — 5개 |

> **오버라이드(Override)**: 프로필 안 효과의 칸마다 왼쪽에 있는 체크. 체크한 값만 화면에 적용된다.

## 정리

- 환경 프리셋(에셋) 하나 = 하늘 + 햇빛 + 환경광(3색) + 안개 + 반사 큐브맵 + Volume 프로필 + 배경 소품.
- 쉐이더는 환경광을 `SampleSH`(546행), 반사를 `GlossyEnvironmentReflection`(551행), 안개를 `MixFog`(611행)로 받는다.
- 반사 프로브는 **구워 둔 큐브맵**을 바꿔 끼운다. Reflection 칸이 비면 직전 환경이 남는다.
- 조명 프리셋(장면 안 값)은 **방향·세기 배수**, 환경은 **색·그림자 진하기**를 정한다.
- Volume은 **복사본이 있으면 원본 칸을 안 본다** → 환경을 바꿀 때 복사본을 버려야 한다.
- 톤매핑은 HDR 밝기를 화면에 담는 규칙(Neutral = 덜 비틂, ACES = 대비 강함), 노출 +1 EV = 2배.

## 확인 질문

1. 새 환경 프리셋의 Reflection 칸을 비워 두고 노을 → 새 환경 순서로 눌렀다. 갑옷 금속에는 무엇이 비치는가? 왜?
   - **정답**: 노을 하늘(직전 환경의 큐브맵). `SetEnvironment` 153행이 `env.reflection != null`일 때만 프로브의 큐브맵을 바꾸기 때문.
2. 고치기 전 코드에서 `volume.sharedProfile`을 다른 프로필로 바꿨는데 화면 후처리가 그대로였다. 왜인가?
   - **정답**: 처음 `volume.profile`을 읽을 때 복사본이 생기고, Volume은 복사본이 있으면 `sharedProfile`을 보지 않는다(`profileRef`). 복사본을 버려야(`volume.profile = null`) 새 원본으로 다시 복사된다.
3. **Build Test Scene**을 실행한 뒤 내가 만든 "새벽 안개" 에셋은 남아 있는데, "낮은 역광" 조명 프리셋은 사라졌다. 왜인가?
   - **정답**: 환경 프리셋은 Project의 `.asset` 파일(ScriptableObject)이고, 조명 프리셋은 장면 안 `Shader Lab Controller`의 목록 값이다. Build Test Scene은 장면을 새로 만들며 조명 프리셋을 기본 7개로 다시 채운다. (환경 에셋도 **Environments** 목록에서는 빠지므로 다시 넣어야 한다.)
